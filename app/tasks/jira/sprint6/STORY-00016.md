# STORY-00016: Fix MOCK_MARKERS data model bug

**Epic**: E-001 Data Quality
**Sprint**: Sprint 6
**Points**: 1
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a developer, I want MOCK_MARKERS to have all fields that HikingScreen and MapHistoryScreen reference, so that the app does not render undefined values.

## Expected Result
All MOCK_MARKERS entries have `title`, `note`, `distanceM`, `timeAgo` fields. No undefined renders in marker detail sheets.

## Acceptance Criteria
- [ ] `MOCK_MARKERS[*].title` exists (string, e.g. "安全警告", "景观点", "水源补给")
- [ ] `MOCK_MARKERS[*].note` exists (string, descriptive note)
- [ ] `MOCK_MARKERS[*].distanceM` exists (number in meters)
- [ ] `MOCK_MARKERS[*].timeAgo` exists (string, e.g. "2小时前")
- [ ] HikingScreen marker detail sheet renders all fields without undefined
- [ ] MapHistoryScreen flags tab renders all flag titles without undefined

## Dependencies
- None — unblocked

## Notes
Bug identified in Sprint 6 planning. HikingScreen.MarkerDetailSheet reads `m.title`, `m.note`, `m.distanceM`, `m.timeAgo`. MapHistoryScreen flags tab reads `m.title`, `m.note`. mockData.ts MOCK_MARKERS only has `id`, `type`, `text`, `author`, `minutesAgo`.
