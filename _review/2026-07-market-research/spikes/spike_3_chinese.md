# Spike 3: 中文源爬取可行性

## 结论

- **小红书 (xiaohongshu.com)**: **不能** — 3 家搜索引擎（Zhipu/Quark/Sogou）返回 30 条结果里 0 条来自 xiaohongshu.com。反爬极强,需要登录+签名,MCP 工具集碰不到内容。
- **知乎 (zhihu.com)**: **能** — webSearchPro 返回 2 条 zhihu.com 链接带完整摘要；webReader 直接 fetch 知乎问答 URL 返回完整正文（answer 内容 + 图片链接 + 元数据 + upvote/comment count + dateModified）。无需登录。
- **豆瓣 (douban.com)**: **部分** — 话题页(gallery/topic)可以搜到并有摘要；豆瓣小组内容主要通过微博二次转发露出。豆瓣笔记页(m.douban.com/note)可搜到。webReader 未直接测试,但结构与知乎类似,应可 fetch。
- **微博 (weibo.com)**: **部分** — 搜索能返回 weibo.com 链接和短摘要（如"我的世界迷雾经历了横跨美国的搬家也只有106级...一生足迹这个app做的更好"这种真实用户评价）。长内容/评论/图片需登录。
- **额外发现**: 简书(jianshu.com)、少数派(sspai.com)、爱范儿(ifanr.com)、36氪 是中文源里最富信号的替代——直接可爬,内容深度远超小红书短笔记。

## 各方法评测

### webSearchPro (ZhipuAI GLM)
**评分: 5/5**

返回样本（真实结果，非猜测）:
1. **知乎问答** "有什么基于百度地图或者高德地图，能记录足迹的app？" — 完整摘要 500 字,含 OysterX vs 世界迷雾 vs 苹果/安卓对比,直接可用
2. **36氪长文** "用 App 记下走过的路，除了世界迷雾还有 10+ 个值得一试的 App" (2024-01-08) — 深度评测多资料库、快照、UI 演变
3. **简书评测** "轨迹记录APP的横向对比评测（世界迷雾、我的路、探索世界）" — iPhoneX iOS 12.1.4, 68RMB 付费用户画像,下载量数据
4. **知乎神器合集** — 世界迷雾"要用一生去实践"的用户评价,列出成就系统/护照/徽章使用感受
5. **少数派** "不用世界迷雾,还有这些工具来处理足迹" (2024-01-05) — 竞品对比

摘要长度: 400-600 字/条,足够判断内容相关性。

### webSearchQuark (夸克)
**评分: 4/5**

返回样本:
1. **爱范儿** Polarsteps 深度评测（2016 早期评测,500 字摘要）
2. **小众软件 (appinn.com)** 徒步 GPS app 横评（六只脚、Polarsteps、OysterX、世界迷雾）
3. **今日头条 (toutiao.com)** 徒步 app 长文回答,含 GPX tracker/两步路户外助手/高德地图三家真实用户对比

覆盖面稍偏"下载站"和"apps.apple.com",但真实评测内容仍达 3-4 条。

### webSearchSogou (搜狗)
**评分: 3/5**

主要返回下载站页面（duote/2265/爱吾），信号密度较低。但抓到 1 条极高价值内容:
- **微博用户"走吧哈苏风"** 真实原话: "我的世界迷雾经历了横跨美国的搬家也只有106级...我觉得一生足迹这个app做的更好,可惜只在iphone有"——这是**真实老用户的横向对比**,极有价值。
- **少数派完整文章** — "不用世界迷雾,还有这些工具来处理足迹"

对下载站有偏向,对社区讨论覆盖弱于 Pro。

### webReader 直接 fetch 知乎
**URL 测试**: https://www.zhihu.com/question/46414801

返回内容质量: **优秀**
- 完整 answer 正文（1500+ 字符）
- 图片 CDN 链接（zhimg.com）
- 元数据: viewCount 缺, upvoteCount, commentCount, dateCreated/dateModified, answerCount
- 作者名字
- 关键词 tags: "徒步,应用程序（软件）,户外运动,百度地图,高德地图（Amap）"
- **无需登录,无反爬**

**局限**: 只返回问题详情页第一屏可见的 1-2 条 answer, 长回答列表需要分页 URL 或滚动加载,单次 fetch 拿不到全部 30+ answer。

### playwright 小红书
**未消耗 tool call 执行 (决策省 quota)**

理由: 3 家搜索引擎跨 30 条结果 0 命中 xiaohongshu.com,意味着即使 playwright 打开也会被:
1. 强制登录墙 (2024 起小红书 web 端未登录看 3-5 秒就跳登录)
2. 内容通过 JS 加密渲染,DOM 不含明文
3. IP/指纹反爬

结论: playwright 对小红书**不划算**——即使技术上能突破,单条笔记的 tool call 成本极高(登录/滑块/CSRF token)。放弃。

## 推荐方案

**中文源优先用 webSearchPro (ZhipuAI GLM)**——摘要质量最高、覆盖知乎/36氪/简书/少数派/百度经验/微博等主要中文源。

**执行预算** (4 个 keyword × 平均 1 次 search + 1 次 webReader 深挖):
- 4 × webSearchPro = 4 tool calls, 每次拿 10 条含 400-600 字摘要
- 2-4 × webReader 深挖高信号知乎/36氪长文 = 2-4 tool calls
- **总计约 6-8 tool calls, 预计拿到 30-40 条真实中文用户/评测讨论**

**内容类型分布** (基于本次采样):
- 知乎 answer/question: 6-8 条(直接可爬全文)
- 36氪/爱范儿/少数派长评测: 4-6 条(直接可爬)
- 简书/百度经验对比文: 4-6 条
- 微博真实用户短评: 2-4 条(摘要级)
- 豆瓣话题/小组转发: 2-3 条

## 无法爬的部分（老实说）

1. **小红书笔记正文** — 3 家搜索引擎不索引/严屏蔽,playwright 单条成本过高。**放弃**。替代: 用 36氪/爱范儿/少数派的评测文章替代小红书短笔记的作用。
2. **豆瓣小组内讨论帖全文** — 微博能拿到二次转发摘要,原帖需要豆瓣登录。**部分可得**。
3. **知乎多 answer 分页** — 单次 webReader 只拿到问题详情页首屏,若某问题有 50 条 answer,后 48 条不可得。**部分可得** (可通过在 search query 里换关键词间接抓到高赞 answer)。
4. **微博评论区** — 只能拿到主帖摘要,评论互动内容不可得。
5. **微信公众号文章** — 完全不在搜索引擎覆盖范围内 (weixin.qq.com 反爬)。**放弃**。

**总评**: 中文源 60-70% 的公开评测/长文/知乎内容可爬,小红书笔记/公众号是明显盲区。若市场调研目标是"抓 fog-of-war app 中文口碑",这套方法完全够用;若目标是"抓年轻用户在小红书上的短笔记原话",需要额外投入。
