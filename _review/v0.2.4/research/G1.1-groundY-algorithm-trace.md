## Y 坐标决策树

```
SPAWN-TIME Y DECISION
├─ Path A: GroundYResolver.QueryGroundY() — Preferred
│  ├─ Tier-A: ARPlane.center.y
│  │  └─ Conditions: PlaneAlignment.HorizontalUp + PlaneClassifications.Floor
│  │     + plane.center.y < camera.y - HEIGHT_OFFSET_MIN(0.8m)
│  │     + area >= 1.5m² (or 2.0m² at marginal height)
│  │     + AABB containment check
│  │
│  ├─ Tier-B: ARRaycastHit.pose.position.y
│  │  └─ Raycast types: PlaneWithinPolygon | Depth | PlaneEstimated(A11 fallback)
│  │     + Same HEIGHT_OFFSET_MIN gate as Tier-A
│  │
│  └─ Tier-C: NULL (DEPRECATED in v0.2.3 Branch B)
│     └─ Returns false → spawn REJECTED
│
├─ Path B: ForceFallbackSpawn (CairnAcquireController) — ONLY when >15s in ACQUIRE state
│  └─ fallbackY = max(camera.y - 1.5f, observedMinFloor - 0.05f)
│     └─ observedMinFloor = raycast(camera → down) through FloorPlaneValidator
│
└─ Path C: RN-provided Y (data.y) — NO LONGER USED in Branch B
   └─ Rejected if QueryGroundY succeeds (Tier A/B wins always)
```

## 5 个根因(详见 subagent 报告 §11)

### Root Cause #1: Spawn-time Tier-A 漏判(provisional plane)
- ARKit 没收敛时报错 plane 高度
- Tier-B raycast hit 比 Tier-A 慢但更稳定
- 结果:spawn 时 Y 可能高 ±0.3-0.5m
- 严重度:**HIGH**

### Root Cause #2: Fallback 公式 `camera.y - 1.5f` 错误启发
- CairnAcquireController:601 `fallbackY = camera.y - 1.5f`
- 写死的 1.5m 持机高度假设
- 斜坡 / 蹲下 / 举高时**错 0.2-0.8m**
- 严重度:**CRITICAL**

### Root Cause #3: Lerp 速度被人眼感知
- GroundYResolver:709 fastSpeed=2.5m/s,slowSpeed=1.0m/s
- 0.5m 偏差需 0.2s 完成 lerp
- 60fps 12 帧的下沉肉眼可见 = "飘下来"
- 严重度:**MEDIUM**

### Root Cause #4: Tier-A 升级延迟
- 稳定窗口 1000ms + ARKit classification 不确定
- NZ 山地稀疏地形 plane 一直 refining → stability window keep resetting
- 卡在 Tier-B (raycast,精度差)
- 严重度:**MEDIUM**

### Root Cause #5: ARAnchor 锁住 Y
- GroundYResolver:665 `if (anchored) continue;` 跳过更新
- Fallback Y 错 0.5m 后,ARAnchor 一挂就锁死
- 只有 TryPostFallbackSnap 可以救(30s 窗口,cairn 必须出视野)
- 严重度:**HIGH**

### Design Issue: Cross-session Snap 一次性
- CrossSessionGroundSnap 仅 5s 后跑一次
- 如果用户当时在看 cairn,inView 检查跳过 → 再也不 snap
- 严重度:**LOW-MEDIUM**

## G2 实施方向(参考)

业界做法 (Apple Measure / Pokémon GO / IKEA Place):
1. 用最近 plane 的 raycast hit,**不要持机高度启发**
2. ARCore Geospatial 持续 VPS refinement → 允许 anchor Y 更新(铁律 #1 之外的微调)
3. Death Stranding 风格"snap-to-ground" 视觉动画(0.3-0.5m 修正显示成短暂下降)
4. Oculus Spatial Anchors:多 session 持久化 + 更精 plane 重投影
5. LiDAR 设备优先用 Depth mesh 子 cm 精度
