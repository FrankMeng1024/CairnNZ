## 关键发现总结

### ✅ 当前流程是正确的(v0.2.4)

整个调用链使用 ARKit World 坐标,而非 GPS:

1. **RN 端 (ARScreen.tsx:835-1112)**
   - 读 GPS: `lastCoord` 来自 `expo-location`
   - 读 ARKit: `arFrame.camera/origin/groundY`
   - **关键**: 用 `arFrame.origin` (GPS at session start) 作为参考点投影
   - 输出: `unitySpawnPos {x,y,z}` 是 ARKit world 坐标

2. **Native Bridge**
   - 直接发送 ARKit world coords 到 Unity
   - 不再转换,保持精度

3. **Unity 端 (PortalSpawner.cs:363-809)**
   - 接收 `data.x/z` 是 ARKit world
   - 地面检测: `GroundYResolver.QueryGroundY()` 查询 **Tier-A ARKit plane**,NOT GPS altitude
   - **ARAnchor 挂载**: `arRaycast.Raycast()` → `AttachAnchor(plane, pose)` 同步
   - Container 立刻 parent 到 anchor: `container.SetParent(anchorOnSpawn, false)`

### 🔴 飞天根因清单(3-5 个最可能)

| 根因 | 代码位置 | 状态 |
|---|---|---|
| 1. sessionOffset per-frame virtualOrigin (v210) | RN bridge | ✅ v0.2.4 fixed |
| 2. ARAnchor 挂载延迟 1s (v186) | PortalSpawner:336 | ✅ v0.2.3 fixed |
| 3. **无平面时 fallback free-floating** | PortalSpawner:620-627 | ⚠️ 仍存在 |
| 4. groundY = camera.y - 1.3m (v206 前) | PortalSpawner:370 | ✅ v0.2.3 fixed |
| 5. **arOrigin 初始化前用 live GPS** | UnityAROverlay:802 | ⚠️ 不够稳定 |

### 🎯 三大仍存在的风险

**1. 无平面无 LiDAR 时 container free-floating**(PortalSpawner:620-627)
- 墙壁/天花板/室内无纹理 → 无 ARKit plane detection
- Container 无 parent anchor → ARKit frame 漂移时跟着飘
- 下次冷启 AR session → 位置完全错位

**2. arOrigin 初始化延迟**(useMarkerStore)
- 需要 GPS lock 30s+ 以后
- 之前 plant 的 marker 用 live GPS 参考 → 不稳定

**3. PlaneDetected 仍可能误认 tabletop**(虽已改进)
- 多层楼房/架子房间
- 底-三分位 filter 还不够完美

## 2026-06-13 补充(主 agent 二次 trace,A2.1 收尾后追加)

### 发现:cross-session re-render 路径仍走 GPS

**Same-session plant 路径**(`ARScreen.tsx:1097-1102`,A2.1 已修锚定):
```ts
unityOverlayRef.current.spawnCairn({
  id: marker.id, type, x: unitySpawnPos.x, y: unitySpawnPos.y, z: unitySpawnPos.z, ...
});
```
直接传 ARKit world (X,Y,Z),不走 GPS 转换。这条路径 A2.1 commit 1e11cc2/2d90e08/ac77a96 已修 anchor 锚定。

**Cross-session re-render 路径**(`unityCairnSpawn.ts:132-161 buildSpawnRequest`,**飞天真根因**):
```ts
const xz = geoToArkitWorld(marker.lat, marker.lng, origin);
// dN = (markerLat  - origin.lat) * 111_000
// x  =  dE = (markerLng - origin.lng) * cos(origin.lat) * 111_000
// z  = -dN
return { x: xz.x, y: groundY ?? 0, z: xz.z, ... };
```

**问题链**:
1. Marker schema (`useMarkerStore.ts:23-49 interface Marker`) 只存 `lat/lng/alt`,**完全没有 ARKit world XYZ 字段**
2. `arOrigin` 是 session start 的 GPS 锚点,持久化在 AsyncStorage(line 62-65 `AR_ORIGIN_KEY_PREFIX`)
3. App 重开 → 同一 origin → 理论上 `geoToArkitWorld(markerLat, origin)` 算出来的 (x,z) 应该一致
4. **但 GPS lat/lng 持久化时已经吞了 GPS 漂移**(plant 时 GPS noise ±5-15m),反推 ARKit world 时这个误差不会消失,而且 ARKit 实际 origin 跟存储 origin 之间还有自己的 drift
5. → 用户原话"每次打开都飘逸 甚至飞到天上"

**用户原话 mapping**:
- "AR plant 的 mark 没用 arkit 的世界坐标" → ✅ 证实,marker 持久化只有 GPS lat/lng,没有 ARKit XYZ
- "用的是 GPS" → ✅ 证实,buildSpawnRequest 反算 ARKit XYZ 的输入是 GPS lat/lng
- "每次打开都飘逸" → ✅ 证实,session 间 ARKit world frame 不一致 + GPS noise 累积
- "甚至飞到天上" → ✅ y=groundY ?? 0,session 间 groundY 不同(camera-relative),早期 session 没 ARKit plane 走 fallback 真的可能 y=0 即用户脚下,新 session camera 在不同高度 → 视觉 "飞天"

### A2.2/A2.3 修法落地点

**A2.2 — 双源 schema**(`useMarkerStore.ts:23-49 interface Marker`):
- 新增 `arkitX: number | null` / `arkitY: number | null` / `arkitZ: number | null` 字段
- 新增 `arOriginLat: number | null` / `arOriginLng: number | null` 字段(plant 时的 origin 快照,for 反算合法性 sanity check)
- Migration:旧 marker 这些字段 = null(走 GPS fallback path)

**A2.2 — Plant 时填字段**(`ARScreen.tsx:1071-1085 addMarker`):
```
addMarker({
  ...,
  arkitX: unitySpawnPos.x,   // hit-test 出来的 ARKit world
  arkitY: unitySpawnPos.y,
  arkitZ: unitySpawnPos.z,
  arOriginLat: arOrigin.lat,
  arOriginLng: arOrigin.lng,
})
```

**A2.3 — `buildSpawnRequest` 优先 ARKit XYZ**(`unityCairnSpawn.ts:132`):
```
if (marker.arkitX != null && marker.arkitY != null && marker.arkitZ != null) {
  // Tier-A: 直接用持久化的 ARKit world,前提是同一 origin
  return { x: marker.arkitX, y: marker.arkitY, z: marker.arkitZ, ... }
}
// Tier-B: fallback GPS+raycast (现有逻辑)
const xz = geoToArkitWorld(marker.lat, marker.lng, origin);
...
```

**陷阱**:同一 ARKit session 内的 anchorX/Y/Z 在 cross-session 不直接可移植 — ARKit 重启后 world frame 旋转/位移变了。Tier-A 必须配 ARWorldMap 持久化(用户原话"必须保证 mark 在同一点位 不管手机如何摆放" 同 session 内 ✅,跨 session 需要 ARWorldMap 才严格)。

**临时 cross-session 策略**:
- arOriginLat/Lng 跟当前 arOrigin 比对(< 5m delta)→ 直接用 arkitX/Y/Z
- arOrigin 已变(用户走远了 / 重 GPS lock)→ fallback `geoToArkitWorld(marker.lat, ..., currentOrigin)` 现有路径
- 这是 v0.2.4 不引入 native ARWorldMap 的最大可达提升
