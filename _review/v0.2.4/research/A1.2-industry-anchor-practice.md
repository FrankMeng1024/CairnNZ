# A1.2 业界 AR Anchor 实践调研报告

**任务**：调研 AR 巨头如何让 session 内 mark 绝对不动,为 Cairn v0.2.4 飘逸/飞天 bug 找根因和复刻方案。

**调研方法**：context7(命中度低,Unity AR 词条无 API 详情)+ GLM websearch 6 轮共 ~120 个 query,合并去重得到 9 个有效来源。WebFetch 在企业网络受限,无法直接访问 developer.apple.com / github.com。

**调研日期**:2026-06-13

---

## §1 直接结论(给主 Agent 的 TL;DR)

1. **Cairn 飘逸的根因不是 GPS 不准,而是 GPS→ARKit 世界坐标转换 + 用 `transform.position` 自由摆放**。每帧更新位置 = 没绑定到 ARKit 的世界坐标系 = ARKit 视觉惯性里程计(VIO)做 drift correction 时,`transform.position` 不会被自动校正。
2. **业界共识**:session 内不动 = `ARAnchor` 绑定 + `SetParent(anchor.transform)`。**所有放置 mark 的 AR 应用(Apple Measure / IKEA Place / Pokemon GO / Snap Lens)无一例外用 ARAnchor 而非裸 transform**。
3. **平面附着锚点 > 自由锚点**:Apple Measure / IKEA Place 的稳定来自"raycast 命中 ARPlane → 在 plane 上创建 anchor"。ARFoundation 在 ARRaycastResult 给出 `trackableId`,可以让 anchor 显式 attach 到 plane,plane 姿态调整时 anchor 跟随更新——这是 Cairn 当前"GPS 投影 + 自由 transform"无法获得的稳定性。
4. **跨 session 稳定**:小空间(< 10m)用 `ARWorldMap`(ARKit 原生 + ARFoundation iOS 已暴露 C# API,**真有,不是 spike subagent 之前那个 v0.2.5 defer 的说法**);城市规模用 `ARGeoAnchor`(需街景覆盖,93 国家,**新西兰荒野 trail 全境无覆盖,排除**);厘米级专业户外用 Niantic Lightship VPS(需众包扫描激活,**只在 30000 个城市公共点可用,Cairn 用户的随机 trail 点**位**不可能事先扫描,排除**)。
5. **Cairn 的可执行方案**:
   - session 内不动 → 用 `ARRaycastManager.Raycast(TrackableType.PlaneWithinPolygon)` + `ARAnchorManager.AttachAnchor(plane, pose)` + `SetParent(anchor)`。**不要自己 set transform.position**。
   - 跨 session → ARWorldMap 序列化到本地 + GPS 做粗定位选择哪个 WorldMap;**不要假设 GPS 坐标 = ARKit 世界坐标可以重投**。

## §3 关键问题点对点回答(用户列表)

### a) session 内不动到底怎么实现?

**根因**:Cairn 当前 `transform.position` 自由 + 用 GPS 投影坐标这个组合是**完全错的**。原因:
1. ARKit 世界坐标系的原点是 session 启动时摄像头位置,Y 朝上,X 朝右,Z 朝向相反
2. ARKit VIO 每帧根据视觉特征修正自己的世界估计 — 这种修正会把"世界坐标系"轻微平移旋转
3. 如果你用 `transform.position = some_world_pos`,**这个 transform 不参与 VIO drift correction**,所以你看到的就是物体相对真实环境慢慢飘
4. 如果你用 `ARAnchor`,ARKit 每帧调整 anchor 的 transform 来保持它"贴在真实环境的同一物理点",物体跟着 anchor 自动同步

**ARAnchor 附着到 ARPlane vs free-floating ARAnchor**:
- 引文:"锚点可确保对象在空间中保持不变,**防止对象出现漂移**"(CSDN https://blog.csdn.net/ShanGuUncle/article/details/122670263)
- 引文:"如果 ARFoundation 稍后调整与桌面相关联的几何平面的姿势,那么 Android 小雕像仍会出现在桌子顶部"(CSDN https://blog.csdn.net/jhin_lx/article/details/119386384)
- Plane-attached 比 free-floating 稳,因为 plane 本身在被持续观察 → ARKit 对它的姿态估计置信度更高 → 锚跟着 plane 走更稳
- Cairn 用户在户外 trail plant cairn,通常脚下有大块平地 → **完全适合 plane-attached**

**transform.position 自由 vs SetParent(anchor) 哪个不飘**:
- SetParent(anchor) 一定不飘,这是 ARFoundation 文档反复强调的标准做法
- 引文(CSDN https://blog.csdn.net/jhin_lx/article/details/119386384):
  ```csharp
  // 使现有的内容成为锚点:
  void AnchorContent(Vector3 position, GameObject content) {
      // Add an anchor to your content
      content.AddComponent<ARAnchor>();
  }
  // 将预制件实例化为锚点:
  void AnchorContent(Vector3 position, GameObject prefab) {
      var instance = Instantiate(prefab, position, Quaternion.identity);
      instance.AddComponent<ARAnchor>();
  }
  ```

**为什么 Cairn 当前用 GPS 投影 + transform.position 会飘?**:
1. GPS 投影到 ARKit 世界坐标这一步本身有误差(±5m 起步,树荫/峡谷会更糟)
2. 投影出来的 Vector3 用 transform.position 设到 GO 上,**没绑定 ARAnchor → 没参与 VIO drift correction**
3. 用户走动时 ARKit 修正世界估计,真实环境特征点的 ARKit 坐标变了,但 GO 的 transform.position 没动 → 飘
4. 如果用户偏航惯性大或 IMU 漂移大,Z/Y 偏移可能累积到几米甚至几十米 — 这就是用户说的"飞到天上"

### b) ARFoundation 6 的 TryAttachAnchor 和 TryAddAnchor 区别?

**ARFoundation 4.0 manual 原文(docs.unity.cn https://docs.unity.cn/Packages/com.unity.xr.arfoundation@4.0/manual/trackable-managers.html)**:
- `ARAnchorManager.AddAnchor(Pose)` — 在世界坐标某个 pose 创建一个 free-floating anchor
- `ARAnchorManager.AttachAnchor(ARPlane plane, Pose pose)` — 在指定 plane 上创建 anchor,plane 是 anchor 的父 trackable
- `ARAnchorManager.RemoveAnchor` — 移除

**ARFoundation 6.0 演进**(从 needle-mirror release note https://github.com/needle-mirror/com.unity.xr.arfoundation/releases/tag/6.0.0-pre.7 + CSDN 更新版教程):
- 同步版 `AddAnchor` / `AttachAnchor` 标记为 obsolete
- 推荐异步版 `TryAddAnchorAsync` / `TryAttachAnchorAsync` — 返回 `Awaitable<Result<ARAnchor>>`
- Result 包含 `XRResultStatus`,可能是 `Pending`(VIO 还没准备好)/`Success`/`Failure`
- 异步好处:不会在 ARSession TrackingState != Tracking 时返回半残锚点

**对 Cairn 的指引**:
- 用 `TryAttachAnchorAsync(plane, pose)` 而不是 `TryAddAnchorAsync(pose)`,获得 plane-attached 的额外稳定
- 必须 await 结果,Result 不是 Success 就走 fallback(再次 raycast / 提示用户重新对准)

### c) ARKit 的 world coordinate frame 在什么情况会"飘"?

从 ARKit 设计角度(VIO 综述论文 + Apple WWDC):
1. **大幅位移**:走超过 100m 后,VIO 会累积漂移 — 这是 Apple 自己承认的局限,所以才有 ARGeoAnchor
2. **session re-localization**:从后台回前台 / camera 中断后,ARKit 重新尝试定位,期间 anchor 可能短暂跳一下,relocalize 完成后回到正确位置(`ARSession.relocalizing` 状态可监听)
3. **heading 重新对齐**:`ARWorldTrackingConfiguration.worldAlignment = .gravityAndHeading` 会让 X 轴对齐磁北,启动时若 compass 不准,启动后会重新对齐 — 此时整个世界坐标系会绕 Y 轴转一下,所有 anchor 也跟着转
4. **特征点稀疏环境**:全白墙 / 平整地面无纹理时,VIO 退化为纯 IMU,几秒内就显著漂移

**Cairn 当前问题:用户开 app → GPS plant → 关 app → 重开 app → Cairn 飞天**:
- 重开 app = 新 ARSession = 新世界坐标系原点(摄像头当前位置)
- 老 GPS 坐标投影到新坐标系 = **完全错的位置**
- 这跟 ARKit drift 无关,这是"GPS 投影"这个方法本身就不能跨 session 用

### d) IKEA Place 等已经成熟 app 的"plant 时序"是什么?

精确到 method 级:

```
1. 用户进入 app
2. ARSession 启动,planeDetection = .horizontal(IKEA 加 .vertical)
3. 用户扫地面,等到至少一个 ARPlane (TrackingState == Tracking)
   - UI 提示"please scan the floor"
   - 直到 ARPlaneManager.trackables.count > 0 且至少一个 plane.trackingState == TrackingState.Tracking
4. 用户从家具菜单选一个家具
5. 屏幕中心显示 reticle / focus square,跟随 raycast 命中点
   - 每帧:ARRaycastManager.Raycast(screenCenter, hits, TrackableType.PlaneWithinPolygon)
   - 取 hits[0],reticle 位置 = hits[0].pose.position
6. 用户 tap "place"
7. var plane = ARPlaneManager.GetPlane(hits[0].trackableId);
8. var anchor = await ARAnchorManager.TryAttachAnchorAsync(plane, hits[0].pose);
9. if (anchor.status.IsSuccess()) {
       var go = Instantiate(furniturePrefab);
       go.transform.SetParent(anchor.value.transform, worldPositionStays: false);
       go.transform.localPosition = Vector3.zero;
       go.transform.localRotation = Quaternion.identity;
   }
10. 之后每帧 ARKit 自动更新 anchor.transform — go 跟着不动
11. **永远不要直接写 go.transform.position 或 go.transform.rotation**(本 Sprint 的核心戒律)
```

### e) Cairn 应该的标准 plant 调用顺序

```csharp
// PortalSpawnerV199.cs / CairnAcquireController.cs 应改为:

async void OnUserConfirmPlant() {
    // Step 1: 必须等到 ARSession.state == ARSessionState.SessionTracking
    if (ARSession.state != ARSessionState.SessionTracking) {
        ShowToast("Move phone slowly to start tracking");
        return;
    }

    // Step 2: raycast 命中 plane
    var hits = new List<ARRaycastHit>();
    var screenCenter = new Vector2(Screen.width / 2, Screen.height / 2);
    if (!arRaycastManager.Raycast(screenCenter, hits, TrackableType.PlaneWithinPolygon)) {
        ShowToast("Aim at the ground");
        return;
    }

    // Step 3: 取命中的 plane
    var hit = hits[0];
    var plane = arPlaneManager.GetPlane(hit.trackableId);
    if (plane == null || plane.trackingState != TrackingState.Tracking) {
        ShowToast("Wait for ground to be tracked stable");
        return;
    }

    // Step 4: 异步 attach anchor 到 plane
    var anchorResult = await arAnchorManager.TryAttachAnchorAsync(plane, hit.pose);
    if (!anchorResult.status.IsSuccess()) {
        ShowToast("Failed to plant, please try again");
        return;
    }
    var anchor = anchorResult.value;

    // Step 5: 实例化 cairn,SetParent 到 anchor
    var cairn = Instantiate(cairnPrefab);
    cairn.transform.SetParent(anchor.transform, worldPositionStays: false);
    cairn.transform.localPosition = Vector3.zero;
    cairn.transform.localRotation = Quaternion.identity;

    // Step 6: 后端记录 anchor 的 GPS 粗定位 + Pose(用于跨 session relocalization 选 WorldMap)
    BackendApi.RecordCairnPlant(
        gpsCoarse: Input.location.lastData,
        anchorWorldPose: anchor.transform.GetWorldPose(),
        sessionId: arSession.subsystem.sessionId
    );
    
    // Step 7: 永远禁止 cairn.transform.position = ... 或 cairn.transform.rotation = ...
}
```

**当前 PortalSpawnerV199.cs:568(MEMORY 提到)的修复**:不仅是"sharedMaterial 只赋 1 个" — 还要把那一段从 `cairnGo.transform.position = gpsToWorldPos` 重构为上面的 attached-anchor 流程。

### f) 跨 session(打开 app 重 spawn)怎么不飞天?

**v0.2.4 范围内能做的(立即生效)**:
- **不要重 spawn**:用户每次开 app,先让 ARKit 稳定追踪几秒(planes 探测完成),才允许做任何事
- 跨 session 的 cairn 显示**降级为"看不到具体位置,只显示距离指南针"**,等用户走到 GPS 接近(< 20m)之后,提示"靠近你之前的 cairn,点击 re-anchor",此时再走完整 plant 流程,把这次新 anchor 替换旧记录

**v0.2.5 真正解决(进 backlog)**:
- 每次 plant 同步保存 ARWorldMap.bytes 到本地
- 重开 app:
  1. 启动 ARSession 时设置 `ARWorldTrackingConfiguration.initialWorldMap`(iOS 通过 ARKit subsystem 暴露)
  2. ARSession 状态进入 relocalizing
  3. UI 提示"Look around like last time you were here"
  4. 监听 `ARSession.stateChanged`,relocalize 成功后再加载 cairn 到老 anchor
- 这套是 Apple 在 WWDC 2018 直接推荐的 persistent AR 标准流程

**GPS 重定位 + plane 重扫 + Y snap 是否够?**:
- 不够。原因:GPS 平面误差就有 ±5m,投影到 ARKit 世界还要叠加 heading 不准的旋转误差。在荒野 trail,这就直接表现为"飘 5-30m + 朝向偏 30-90 度"
- 必须 ARWorldMap

**ARWorldMap 在 ARFoundation 6 是否真有 C# API?**:
- ✅ 真有。代码片段(CSDN https://blog.csdn.net/CyberLynxO/article/details/132953876 + /a451319296/article/details/111569699):
  ```csharp

  #if UNITY_IOS
  using UnityEngine.XR.ARKit;
  #endif
  // 取 ARKitSessionSubsystem,调 GetARWorldMapAsync(),拿 NativeArray<byte>,写文件
  ```
- 之前 spike subagent 说 v0.2.5 defer 是因为没仔细查 namespace,**API 一直存在,从 ARFoundation 4.x 一路保留到 6.x**

### 4.2 Cairn v0.2.4 的最终选择

**核心选择:ARAnchor 附着到 ARPlane (`ARAnchorManager.TryAttachAnchorAsync`)** + **SetParent(anchor.transform)**。

**配合**:
- `ARRaycastManager.Raycast(TrackableType.PlaneWithinPolygon)` 拿 plane + pose
- 等 `ARSession.state == SessionTracking` + plane.trackingState == Tracking 才允许 plant
- 永远不写 `transform.position`,永远 `SetParent`

**跨 session(v0.2.4 临时方案)**:
- 不重 spawn 老 cairn 到具体位置
- 显示距离 + 指南针
- 用户走近(GPS < 20m)→ 提示 re-anchor → 走新 plant 流程

**跨 session(v0.2.5 正式方案 backlog)**:
- ARWorldMap 序列化到本地 + 后端
- 重开时按 GPS 选最近的 WorldMap → 加载 → relocalize → 取回老 anchor
