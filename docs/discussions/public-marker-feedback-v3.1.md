## 0. 已锁定边界

| 边界 | 决定 |
|---|---|
| route 是否 public | ❌ 永远私人 / group only |
| public 范围 | ✅ 仅 marker（cairn / pin） |
| personal / group marker 反馈 | ❌ 零反馈机制 |
| 投票身份 | ✅ 完全匿名（DS 同源），后端 hashed |
| 是否有踩 | ❌ 无踩，沉底靠时间衰减 |
| 是否有评分 / 评论 | ❌ 无 |
| 是否有反复投票配额 | ❌ 一个 marker 一票，T/F 二态 |

## 1. 反馈形态

```
public marker 上 = 1 + 1:
  👍 匿名 Like      —— 唯一投票动作
  🚩 独立 Report    —— 仅违规内容（不计入投票）
```

### Like 视觉

```
未点：线框大拇指（白色描边，semi-transparent）
已点：填充大拇指（sepia 棕实色 + 轻微辉光）
```

> ⚠️ 落地注意：填充态需视觉测试，sepia 棕饱和度足够让"已 Like / 未 Like" 一眼可分。

### Report 视觉

| 视角 | Report 入口 |
|---|---|
| **AR 视角** | ❌ 不显示（保持现场正向沉浸） |
| **地图 detail sheet** | ✅ 底部不显眼位置（避免误触） |

## 2. 距离分层（3 段）

| 距离 | 渲染 | 操作 |
|---|---|---|
| **>500m** | 不渲染 | — |
| **30–500m** | 聚类点 / 弱化赞数 | ❌ 不可投 |
| **<30m** | 完整 detail + AR | ✅ 可投+可改 |

**临界过渡**：进入 30m 时 detail sheet 顶部淡入提示"你已到达，可以为这个 cairn 留下标记了"。

## 3. 投票触发（解决离线场景）

**任一满足即可**：

- 🛰 **路过验证**：trackPoints 7 天内经过 marker 30m 半径
- 📍 **实时距离**：当前 GPS <30m

> NZ 大量步道无信号，3 天后回家点赞 → 允许（trackPoints 同步后端时验证）

## 4. 投票模型（极简 T/F）

```
该账号对该 marker:
  状态 ∈ { 未投票, 已 Like }
  动作 = Like 或 Unlike
  随时可在两态间切换 (满足距离/时间窗口)
```

**修改窗口**：<30m 或 <24h（任一满足）

**无配额概念**。防刷靠 GPS 路过 + 软权重，不靠次数限制。

## 5. 离线投票（关键）

### 行为

```
离线时（已通过 trackPoints 路过验证）:
  1. 用户点 Like → 写入本地 voteQueue
  2. 数字立刻 +1（本地乐观更新）
  3. 网络恢复 → 自动同步，用户无感
  4. Unlike / 修改同样本机排队

在线时:
  - 直接调 API
```

### 复用现有基础设施

`offlineQueue.ts` 已实现 GPS 离线轨迹 + UUID idempotency。扩展 `voteQueue` 即可。

### 同步冲突处理

```
回连同步时 marker 已被算法隐藏（判定刷屏）:
  → 本地 Like 静默丢弃，不报错
  → UI 上 marker 自动消失
```

## 6. 寿命公式（语言版）

> ⚠️ **核心直觉**：是"距离最后一次有人点赞多久"，不是"距离创建多久"。

### 两个力的拔河

```
让它活：Like 数越多 → 寿命越长
让它死：时间过去没人点 → 慢慢沉
        类型本身易过期（如 danger）→ 沉得快
```

### per-type 基础寿命

| 类型 | 基础寿命 | 为什么 |
|---|---|---|
| ⚠️ danger | **7 天** | 最易变（雪崩、塌方），必须快速重新验证 |
| 💧 supply | **30 天** | 水源会干，营地会变 |
| ↗️ junction | **60 天** | 路口偶有变化 |
| ⛰ scenic | **90 天** | 风景中等（NZ 秋色雪山差异大） |
| 🪨 cairn（留言型） | **180 天** | 留言性质，最稳定 |

### Like 续命表（以 supply 30 天为例）

| Like 数 | 续命 | 总寿命 |
|---|---|---|
| 0 | +0 | 30 天后沉 |
| 1 | +7 天 | 37 天 |
| 5 | +23 天 | 53 天 |
| 10 | +32 天 | 62 天 |
| 50 | +51 天 | 81 天 |
| 100 | +60 天 | 90 天 |

**直觉**：第一票最值钱，越往后边际递减。**避免刷 1000 票永生**。

### 时间重置

```
1月1日 marker 创建
3月1日 第一个 Like  ← 时间从这里重新算
4月1日 才过30天没人理会，marker 还活着
```

→ **一直被点赞 = active = 不需要作者续命**

### 季节休眠 + 2 年硬上限

```
冬季封山区域 → Δt 冻结（DOC 封山日历）
> 2 年 → 强制隐藏，作者 100m 内可"重新创建"
```

## 7. 拥堵处理（好牧羊人小屋实例）

### 真实场景

NZ 最热门拍照点，假设 200 个 public marker 挤在 100m 范围内。

### 三机制依次生效

#### 🛡 机制 A：源头压缩（创建端拦截）

```
新用户走到好牧羊人，想留 "这里风景好":
  app 检测附近 30m 内已有 5 个 scenic marker
  弹窗：
    "附近已有人留下 cairn:
      '日落最美'  ❤ 23
      '湖水蓝色 magic' ❤ 18
      '半小时步行可达' ❤ 12
     你要 +1 哪一个? 还是要新建?"
  
  90% 用户点 +1 (省事 + 表达赞同)
  10% 真有不同信息 (如"小心鸭子") 才新建

→ 200 个潜在 marker 被压缩到 ~20 个
```

> ⚠️ 90% 接受率为假设值，落地后 A/B 验证。若实际 <70% 则强化提示。

#### 📏 机制 B：屏幕密度上限（展示端聚类）

```
zoom > 14（近）: 显示 top 20
zoom 10-14（中）: 显示 top 8（仅聚类）
zoom < 10（远）: K=0，不显示个体

排序: Like + 时间衰减综合得分
剩余: 聚类 "+30" 圆点，点击展开列表，不丢失任何 marker
```

> ⚠️ 作者保护：自己的 marker 即使被聚类，"我的 Marker" 列表始终可见，并显示当前可见性状态。

#### 🎖 机制 C：完成徽章（吸收 brag 需求）

```
你走完 Routeburn Track (3 天 32km)
你想 brag，但 Cairn 不公开 route

折中: 在终点 Howden Hut 处的 public cairn 上贴徽章
  → 选 "Routeburn Track 完走"
  → cairn 显示: "12 人在此完成了 Routeburn Track"

→ 你被认可了，GPX 仍私密
→ 后来人看到，知道这是终点，12 个人都走完
```

**默认 private，作者主动开启才公开展示徽章。**

## 8. AR 投票交互（统一大拇指）

### 触发距离

| 距离 | 显示 |
|---|---|
| > 30m | marker 渲染，detail 不可见 |
| < 30m | marker 上方浮 ViroQuad billboard |

### Billboard 内容

```
┌─────────────────┐
│  💧 Water       │  ← 类型 + 标题
│  ❤ 12           │  ← Like 数
│  [👍 大拇指]    │  ← 可点击按钮
└─────────────────┘
```

### 交互

```
点击大拇指:
  - 立刻填充, +1 数字
  - Heavy haptic 触觉反馈
  - 一道粒子从用户飘向 marker (1s)
  - 不发声 (户外默认静音)

撤销:
  - 已 Like 状态下大拇指变实色
  - 长按 1.5s → 撤销 (反向粒子动画)
```

> ⚠️ Hit area 比视觉 area 略大（fat finger 容错）。

> ⚠️ AR 视野内 billboard 上限：屏幕中心 ±60° 内最多 5 个 billboard 同时展开，其余收成"+N more"小标签——避免 30m 内多 marker 重叠遮挡。

### vs v3 凝视方案

| 维度 | 凝视+双击 | **大拇指点击** |
|---|---|---|
| 学习成本 | 高 | 极低 |
| 戴手套 | 困难 | OK |
| 误触 | 低 | 可控（按钮够大） |
| 与地图视角统一 | 否 | **✅ 是** |

## 9. 防刷（攻击经济学）

### 硬约束

🛡 **GPS 路过验证** — 不可绕

**ROI**：偏远 marker 刷 1 票 = 数小时驾车往返 → **严重为负**

### 软权重（用户感知 0）

- 设备指纹聚集（同设备 ≥3 账号）→ 权重 ÷ N
- IP 时空聚集（1h 内 ≥5 账号同 marker）→ 风控审核
- 节奏异常（同账号 1h ≥10 票）→ 权重 ÷ 2
- 历史质量 → ±20%

✅ **新用户零门槛**，不打击积极性。

### 残余风险（接受）

5 个朋友现实约定开车去刷票——成本/收益比已不划算，统计上风控可识别。

## 🔟 申诉三层化（避免人工核心）

### 层 1: 算法自动隐藏

**触发条件（任一）**：

- 5 个独立 IP + 7 天内 + 同原因码（spam / hate / safety_misinfo）
- 关键词黑名单命中（脏话 / 仇恨词 / 广告 URL）
- 创建后 24h 内 0 Like + 3 举报

**结果**：marker 自动隐藏 → 作者推送通知（如 opt-in）"已被举报隐藏，可申请复审"

### 层 2: 社区自助复审（无开发者介入）

```
作者点 "申请复审":
  1. marker 重新展示给"最后路过该 marker 的 10 个用户"
  2. 给他们一次性投票: "这个 marker 是否合理? Y/N"
  3. 多数 Y → 自动恢复
  4. 多数 N → 维持隐藏

→ 用社区力量验证, 不要开发者判断
→ DS 风格的"集体良知"
```

**兜底规则**（subagent 提出）：

```
14 天窗口期内"最后路过的 10 个用户"凑不齐:
  → 候选池扩大到 "附近 1km 内最近路过的 30 人"
  → 仍凑不齐 → 升层 3 (人工)
```

### 层 3: 人工（极罕见 < 1 条/月）

**触发**：

- 自助复审平局
- 法律敏感（毛利 Tapu / 隐私曝光 / 涉嫌违法）
- 单一用户被多次申诉

**当前阶段**：你自己处理。
**> 1000 用户后**：DOC 志愿者 / Tramping Club 老 tramper moderator 体系。

### ⚠️ 不需要真人物理验证 marker 位置

DS 模型核心：**信息真实性靠社区，不靠权威**。算法 + 时间 + 社区三层，足够。

## 1️⃣1️⃣ DOC 官方数据 → public marker（解冷启动）

### 数据来源

NZ DOC 公开 API/CSV：
- 11 条 Great Walks 的 hut 位置
- water source 位置
- 已知 danger spot
- junction（路标分叉）

### 形态

```
带"DOC verified"盾牌徽章的 public marker
- 视觉: sepia 棕统一 (与 PRD3 DOC 橙呼应)
- 来源标注: "Source: DOC NZ"
- 与用户 marker 同算法 / 同 Like 机制
```

### H 参数策略（subagent 提出的微调）

```
DOC marker 的 H = max(per-type H, 365 天)

举例:
  DOC danger marker → H = max(7d, 365d) = 365 天 (官方数据稳定)
  DOC supply marker → H = max(30d, 365d) = 365 天
  
统一规则: DOC 来源至少活 1 年, 但保留类型语义
```

### 副作用（全是好的）

| 副作用 | 价值 |
|---|---|
| 新用户打开看到密集 cairn 群 | 解冷启动断崖 |
| 用户 Like 持续验证 DOC 数据 | 比 AllTrails 评论可信（GPS 路过验证） |
| DOC 看到数据被 Like | 天然 B2B 合作切入点 |
| 同形态、同算法 | 工程上不分两套系统 |

### vs v3 "只读底图层"

| 维度 | v3 底图层 | **v3.1 转 marker** |
|---|---|---|
| 数据形态 | 蒙在地图上 | 与用户 marker 同形态 |
| 用户认知 | "底图里政府数据" | "原来 Cairn 上有这么多 marker" |
| 是否可 Like | ❌ | **✅** |
| 长期演进 | 永远是底图 | 按算法衰减，DOC 数据更新可重新激活 |

## 附录：数学公式（给 Backend）

```python
# L=0 时 t_last_like = t_create

LifeBoost = H × log10(L + 1) × 24
LifeLeft  = H + LifeBoost - Δt_effective

if LifeLeft < 0:
    hidden (作者可激活)
else:
    DisplayScore = (L + 1) / ((Δt_effective / H) + 1)^G   # G=1.8 (HN 验证值)

# 季节休眠
if is_winter(marker.region, current_date):
    Δt_effective = Δt_at_winter_start
else:
    Δt_effective = current_time - max(t_create, t_last_like)

# 2 年硬上限
if (current_time - t_create) > 730 days:
    forced_hidden = True
```
