# Cairn UI/UX 体检报告（v383）

> **审计日期**：2026-06-29
> **分支**：`audit/v383-ui-ux`
> **截图来源**：55 张真实 Playwright 截图，11 个页面类别
> **评分**：UI 和 UX 双轴独立打分，1–10 分，满分 10
> **方法**：两个独立 AI 评分代理（UI 视角 + UX 视角）平行打分后取均值
> **颜色标识**：🟢 8–10 优秀　🟡 6–7.9 及格　🟠 4–5.9 待修　🔴 1–3.9 紧急

---

## 📊 整体得分

| 总览 | 分数 | 评 |
|---|---|---|
| **UI 平均分** | 🟡 **7.94 / 10** | 设计系统底子扎实，细节 + 毛玻璃没收尾 |
| **UX 平均分** | 🟡 **7.54 / 10** | 故意打磨处极强，micro-moments 全失 |

---

## 🎯 一句话总结

**Cairn 知道好看的样子，做出了 5 个金标准的页面，但好的设计没贯彻到"操作以后的瞬间"。**

- 用户**翻页面、看页面** → 体验 8 分（基本及格甚至优秀）
- 用户**点提交、等加载、出错** → 体验 3–4 分（让用户怀疑 app 坏了）

### 修复方案（白话）

1. **建一个全局"小提示"组件**（不阻塞用户，能从下面或上面冒出来的那种）→ 替换 17 处现在用的"系统弹窗"
   - 保留确认类（删除、登出 → 这种确实需要阻塞）
   - 改成小提示：保存成功 / 添加成功 / 发送成功 / 错误提示
   - **修复影响**：8 处静默失败全部修好

2. **修输入框双层框 bug** → 抽一个统一的"带标签的输入框"组件，所有表单用同一个
   - **修复影响**：所有表单都顺手修了

3. **9 个关键按钮颜色换成主色绿** ("Looks right" / "Got it" / "Plant Cairn" 等)
   - **修复影响**：app 不再像"在劝你小心每一步"

4. **清除 6 处开发占位字样** ("Real Map (EAS Build)" / "[dev] 标记预览" / "Sprint 68 STORY-XXX" / "v385 检查失败")
   - 全部藏在"只在开发模式显示"的开关后面
   - **修复影响**：app 不再"看起来没做完"

5. **建一个"占位骨架屏"组件 + 给所有加载加 10 秒超时回退**
   - 替换 19 处现在用的"转圈"
   - **修复影响**：弱网下不再"卡死感"

6. **Plant 灰色按钮上方加一行提示**："请先填标题"（或实际的门控条件）
   - **修复影响**：用户不再反复点不动的按钮

7. **抽统一按钮组件**（确认绿按钮 / 次要按钮 / 圆形图标按钮）
   - **修复影响**：以后不会再出现颜色不一致

## 🧠 经验教训（下次直接用）

### 技术经验

- **Cairn web 默认就在已登录状态**（因为 `isPlaywrightBypass` 在 dev 构建里默认开），所以脚本直接落 HomeScreen，不用做登录注入
- **RN 的 Stack 导航器不卸载旧页面**，旧页面 DOM 还在但 hidden，所以选择器一定要加可见性过滤（`visibility !== hidden && opacity > 0`）
- **RN 的 ScrollView 不响应 window.scrollTo**，要用 `page.mouse.wheel(0, 400)` 才能真滚
- **RN-Web 的 Alert 弹窗是 window.confirm**，要先注册 dialog 事件再点触发按钮，否则截不到
- Mapbox 在 web 上自带 fallback `Real Map (EAS Build)` 提示，**不用做 Mapbox 黑盒处理**

### 评分经验

- **2 个独立评分代理（UI + UX）平行跑** = 4 眼验证。两个不同角度同时给出相同优先级 = 最强信任信号
- **打分维度要 8–10 个**，太少（如 3 个）信息量不够，太多用户看不过来
- **打分用 1–10 分而不是 1–5 分** = 颗粒度更细，扣分原因更清楚
- **每个分数都要有扣分原因** = 用户能看懂为什么不是满分，能针对性修
- 颜色标识（🟢🟡🟠🔴）让用户一眼能扫到要修的地方

### 报告经验

- **跟产品经理沟通 = 白话**。技术词全部换：
  - "blocker" → "紧急修复"
  - "drift" → "不一致"
  - "loading state" → "加载状态"
  - "static visual fidelity" → "看起来好不好看"
  - "behavior" → "操作以后的感受"
- **树状结构**比平铺列表好读 — 大页面 → 小操作 → 分数 → 原因
- **金标准 + 必修两个清单**比一长串排名更有用 — 一个告诉团队"保留这些"，一个告诉团队"先修这些"
