## Creation semantics

The deployed registration and verification flow was traced before creation. A successful `/api/auth/verify` transaction creates exactly one verified `users` row with `name`, normalized `email`, bcrypt password hash, and `date_of_birth`; it creates no profile/settings, OAuth, subscription, device-token, push-preference, Activity, Route, Cairn, Memory, friend, or auth-session companion row.

The QA account was created in one direct production DB transaction using that exact verified-user shape, because normal `/register` would send an unwanted verification email. The password was independently generated with cryptographic randomness and hashed using the deployed bcrypt cost 12 implementation. Defaults are `token_version=0`, `account_type=free`, `memory_subscription_limit=5`, `deleted_at=NULL`, and `onboarding_done_at=NULL`. No email was sent.

The human reference account was inspected only for structure. Its full-row digest was identical before and after the operation; it and all of its related data remained untouched.
