# UI Audit — 2026-05-22

This document inventories visual / layout inconsistencies across
Cairn screens. **Nothing here is a fix yet** — it's the input for a
focused UI cleanup pass after the next EAS build is on device.

Use as a reference when picking up a follow-up "design polish" sprint.
Each finding cites file path + line number so it's directly actionable.

---

## 1. Spacing tokens — magic numbers found in styles

`app/src/components/tokens.ts` defines `Spacing.{xs,sm,md,base,lg,xl,xxl}`.
Anywhere `marginTop: 8` / `paddingHorizontal: 12` shows up, it should
use a token.

Sample offenders (non-exhaustive — search `: \d+` in styles):
- `app/src/screens/HikingScreen.tsx:1170` `paddingVertical: 7` (gpsChip)
- `app/src/screens/HikingScreen.tsx:1199` `borderLeftWidth: 3`
- `app/src/screens/HomeScreen.tsx:tools row` `gap: 4` (toolBtn)
- `app/src/screens/RoutesScreen.tsx:filterBarStyles.chip` `paddingHorizontal: 14`
- Various `borderRadius: 16` / `borderRadius: 28` — not in `Radius` token

Action: introduce `Radius.{circle,sheet,small}` if missing; replace.

## 2. Typography — fontSize literals

`tokens.ts` defines `FontSize.{tiny,small,caption,body,h3,h2,h1}`.
But several places use literal numbers:

- `HikingScreen.tsx:1187` value 14, `:1189` unit 9 (tracking stats — was 16/10)
- `ARScreen.tsx` — multiple `fontSize: 12` / `fontSize: 16`
- `HomeScreen.tsx:cardStyles.title` `fontSize: 20`
- `OtaBadge.tsx:label` `fontSize: 11.5`

Action: extend FontSize tokens or accept "intentionally outside scale"
as documented exceptions (with a comment).

---

## 3. Shadow / elevation — multiple recipes

`tokens.ts` defines `Shadow.{card,fab,overlay}`. Many places use raw
shadow props that don't match any preset:

- `HikingScreen.tsx:1198` shadow on trackingBar (offset 8 / opacity 0.1 / radius 24)
- `HikingScreen.tsx:circleBtn` (offset 6 / opacity 0.18 / radius 16)
- `RoutesScreen.tsx:filterBarStyles.chipActive` no shadow
- `OtaBadge.tsx:badge` (offset 2 / opacity 0.1 / radius 6)

Action: codify 3-4 elevation levels (e1 / e2 / e3 / e4) with named
tokens; replace raw values.

## 4. Translucent fills — alpha values vary 0.45 → 0.95

The "frosted glass" language is inconsistent:
- BackButton pillBlur `rgba(255,255,255,0.45)` (post-v11)
- BackButton pillFallback `rgba(255,255,255,0.65)`
- HikingScreen gpsChip `rgba(255,255,255,0.65)`
- HikingScreen circleBtn `rgba(255,255,255,0.65)`
- HikingScreen trackingBar `rgba(255,255,255,0.65)` (post-v11)
- RoutesScreen routePill `rgba(255,255,255,0.85)`
- MapHistoryScreen singleSessionPanel `#FFFFFF` (solid, post-v7 fix)
- OtaBadge badge `rgba(255,255,255,0.96)`

Action: pick 2 standard alphas — `surface-soft` (0.65 over map) and
`surface-solid` (1.0 over neutral bg) — use everywhere.

## 5. Border colours — semi-random rgba

- `'rgba(255,255,255,0.4)'` — most common (correct)
- `'rgba(255,255,255,0.5)'` — circleBtn (slightly different)
- `'rgba(255,255,255,0.6)'` — circleBtn, chip variants
- `'rgba(0,0,0,0.06)'` — OtaBadge badge border

Action: define `Border.{glass, ghost}` tokens.

## 6. Header pattern — top row composition not unified

Each top-level screen has its own header pattern:

- HomeScreen: logo + greeting in one row, no SafeAreaView padding (inset auto)
- HikingScreen: BackButton + GPS chip via topOverlay + topRow flex
- RouteEditorScreen: BackButton + Save button via topOverlay
- SettingsScreen: BackButton + title + Save button via topBar
- ARScreen: just close X via topBar

Two issues:
- inset-aware paddingTop varies: some use `insets.top + 8`, some rely on `<SafeAreaView edges={['top']}>` alone (which has been unreliable when wrapped in `position: 'absolute'` parents — see v11 commit 32ad441).
- BackButton always pill variant; Settings has additional title; AR has no Back at all.

Action: extract a `<ScreenHeader />` component that handles inset +
left/center/right slots so every header has the same vertical
position by default.

## 7. Icon sizing — strokeWidth & size not paired consistently

- Icon `size={14} strokeWidth={2}` (most common)
- Icon `size={16} strokeWidth={2.5}` (chevrons)
- Icon `size={12} strokeWidth={2}` (small chips)
- Icon `size={22} strokeWidth={2}` (compass / flag)

These are roughly OK but a `<TokenIcon variant="chip|action|hero" />`
wrapper would prevent ad-hoc combinations.

## 8. Touch target sizes — accessibility check

- `compassBtn` 44x44 ✓ (Apple HIG min)
- `circleBtn` 56x56 ✓
- chip `paddingVertical: 7 paddingHorizontal: 14` → ~30x55 — borderline
- `permToggle` (RoutesScreen) — small icon-only buttons, may be < 44pt — needs measurement

Action: audit any tap target < 44pt.
