# STORY-00538: Trails Routes Mine|Friends sub-tab + circle routes consume

**Epic**: E-Friend (Friend System v1)
**Sprint**: Sprint 69
**Sprint Goal**: Extend visibility model to Routes + Trails
**Points**: 4
**Owner**: Frontend
**Status**: Done

## Description

Add a Mine|Friends sub-tab to the Routes tab of `RoutesScreen.tsx`. Mine = `useRouteStore.routes`. Friends = subscribed-friend friend-tier routes loaded from Sprint 67 `GET /api/circle/routes`.

## Expected Result

Sub-tab toggle within Routes tab. Mine shows the viewer's own routes (unchanged); Friends shows subscribed-friend friend+public routes. Tapping a Friends route opens it for navigation but NOT for editing (only own routes are editable).

## Acceptance Criteria

- [ ] Sub-tab control rendered inside Routes tab (Mine|Friends, Mine selected by default)
- [ ] Mine view: existing RoutesTab behavior unchanged
- [ ] Friends view: triggers `GET /api/circle/routes` on tab activation
- [ ] Friends view: renders route list — each row shows name, distance, friend's name (Friend-tier) or anonymous (Public)
- [ ] Tap on Friends route opens a read-only route detail (no Edit button)
- [ ] Empty / loading / error states (parity with STORY-00537)
- [ ] Story-535 dependency: routes must persist permission='friend' for them to appear here

## Dependencies

- Sprint 67 STORY-00528: `GET /api/circle/routes` endpoint
- Sprint 69 STORY-00535: Route create UI persists `permission='friend'` (so Friends-tab actually shows seed data)

## Notes

Read-only friend-route detail can reuse the existing route-detail UI by simply hiding the Edit button. Full friend-route navigation (turn-by-turn) is in scope for v1.1, NOT v1.
