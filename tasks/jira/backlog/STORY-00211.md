# STORY-00211: MapHistory — render real Mapbox base map under the track

**Epic**: E-005 Activity History
**Sprint**: Backlog (OTA-deliverable, separate commit to avoid regressing v7 polish)
**Sprint Goal**: TBD
**Points**: 5
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a hiker reviewing my completed activity, I want to see my route drawn on top of a real map (streets, terrain, parks) — not on a flat green panel — so the track has spatial context.

## Why this is its own Story
The existing `MapHistoryScreen` renders the polyline as an SVG over a `Colors.mapBg` background. Replacing that with `@rnmapbox/maps` is structural — it changes how the screen lays out (MapView fills the area, polyline becomes a `LineLayer`, start/end dots become `PointAnnotation`s), and bundling it into the v7 polish commit risked introducing rendering regressions on the same screen we just fixed (the bottom panel transparency leak).

## Expected Result
- The Activity Detail view (single session) shows a Mapbox map filling the area above the bottom stats panel.
- The track is rendered as a Mapbox `LineLayer` styled in the activity colour (Colors.primary for hike, Colors.running for run).
- Start point gets a green dot, end point gets a darker dot/flag, both as `PointAnnotation`s.
- The camera auto-fits to the track's bounding box on mount with reasonable padding.
- If `trackPoints.length < 2`: keep the existing "Activity too short to record path" message — no map rendered (no useful camera).
- Web fallback: keep the current SVG-on-background rendering when `MapView == null`.
