# STORY-00210: AR — Real Camera Background + 4-Corner Draggable Flag Picker

**Epic**: E-003 Marker System
**Sprint**: Backlog (must ship in next native iOS build — not OTA-able)
**Sprint Goal**: TBD
**Points**: 8
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a hiker placing a flag in the field, I want the AR screen to show what my camera actually sees (with my surroundings as the backdrop) and let me drag a flag from any of the four corners onto the centre of the screen, so that placing a flag feels grounded in the real world rather than being a flat compass UI.

This is the **original AR vision** from before Sprint 26 STORY-00071 swapped it out for a bottom-sheet picker (which was done at the time for web compatibility). The current Sprint 51 ARScreen renders a 2D compass on a dark green backdrop — useful as a fallback but not the intended experience.

## Why this is not OTA-deliverable
The implementation requires `expo-camera` (not currently installed). Adding a new native module changes the iOS bundle's native runtime fingerprint, so this Story can only ship inside a fresh `eas build`.

## Expected Result
- ARScreen renders the live rear camera feed as the background.
- 4 flag icons sit one in each corner (Danger / Scenic / Water / Junction). Each is a TouchableOpacity that the user can drag with one finger toward the centre.
- A centre crosshair indicates the placement point. The user drops the flag near the crosshair to confirm placement at the current GPS coordinate (anchored to the user's lat/lng + heading at drop time).
- Existing 2D compass + W/E/N/S labels become an optional overlay (toggleable, off by default once camera is live).
- Falls back to the current dark-green compass-only screen when:
  - The user denies camera permission.
  - Running on a simulator without a camera.
  - Running on web (no expo-camera support).

## Acceptance Criteria
- [ ] `expo-camera` dependency added to `app/package.json` (~17.x for SDK 54).
- [ ] On iOS device, after permission grant, the rear camera feed fills the AR screen (object-fit: cover; full-screen).
- [ ] 4 corner flag icons present, each tappable AND draggable via PanGesture (Reanimated worklet — drag must be jank-free at 60fps).
- [ ] Drop-zone detection: when a flag is released within ~80px of the centre crosshair, it animates into place and triggers the existing `addMarker` flow with the user's current GPS coords.
- [ ] If GPS is unavailable: the corner flags are dimmed to 0.5 opacity with a "Need GPS" pill at the top of the screen.
- [ ] If camera permission is denied: render the existing dark-green compass UI (current behaviour) with an "Enable Camera" CTA that opens `Linking.openSettings()`.
- [ ] X close button retains the `useSafeAreaInsets()` placement from the current Sprint 55 fix.
- [ ] Dynamic Island / notch / no-notch: camera feed reaches the very top of the device (no banding); UI controls (corners, X, Place Flag fallback) honour safe-area insets.
- [ ] Zero runtime errors on device after the placement loop completes.
- [ ] Visual fidelity check against `docs/qa/sprint55-evidence/ar-current.png` shows clear, intentional improvement (camera vs solid colour).

## Dependencies
- `expo-camera` install (native build required).
- Marker placement logic from existing `useMarkerStore.addMarker` is reused (no schema change).
- `useSafeAreaInsets()` — already in use in the file.

## Technical notes
- Use `react-native-reanimated`'s `Gesture.Pan()` + `useSharedValue` for drag handles — same pattern as anywhere else in the codebase that needs PanGesture.
- For drop detection: compare the flag's translated XY against the screen-centre coords (computed once from `Dimensions.get('window')` — recompute on `onLayout` if the screen rotates).
- GPS-to-screen projection: not strictly needed for MVP — the flag is placed at the user's current GPS, the camera background is purely atmospheric. A future enhancement can project nearby marker positions onto the camera plane based on bearing + distance, but that's a separate Story.

## Notes
