# STORY-00212: RouteEditor — snap-to-road sampling via Mapbox Directions API

**Sprint**: Backlog

**Owner**: Frontend Dev

## Description
As a route planner, I want to tap two points on the map and have the editor automatically draw the route along real roads/trails between them — instead of a straight line — so I can sketch a hike route quickly without placing dozens of waypoints by hand.

## Current behaviour (the problem)
RouteEditorScreen treats every map tap as a literal lat/lng waypoint and connects them with straight-line `LineLayer` segments. The user reports this is "too rough" — a tap on Yanping Rd and a tap two blocks away makes a diagonal cutting through buildings, not a sensible walking route.

## Expected Result
- User taps point A → marker. Taps point B → editor calls Mapbox Directions API (`profile=walking` for hike, `profile=cycling` or another sensible default for run) → draws the resolved polyline from A to B along streets/paths.
- Subsequent taps add more legs, each snapped to roads.
- "Undo" removes the last leg.
- "Clear" removes everything.
- Total distance reflects the snapped polyline, not the direct lat/lng-to-lat/lng distance.
- Saved Route stores both the user's tapped waypoints AND the snapped polyline points (so we can replay it without re-querying the API on view).

## Acceptance Criteria
- [ ] Tapping a second point after the first triggers a Mapbox Directions API call (`/directions/v5/mapbox/walking/<lng1>,<lat1>;<lng2>,<lat2>`).
- [ ] Successful response → polyline coordinates rendered as the leg from A to B; total distance updates from the API's `distance` field.
- [ ] API failure → fall back to straight line + a small "Couldn't snap to road" toast; user can keep editing.
- [ ] All snapped polyline points are persisted to `useRouteStore` so re-opening the route doesn't require re-fetching.
- [ ] Mapbox token reused from `EXPO_PUBLIC_MAPBOX_TOKEN` (already in env).
- [ ] Hiking session save-as-route path uses the same snap mechanism if waypoints come from a session sample.
- [ ] Rate limit awareness: don't fire a Directions request on every tap if the user is rapidly tapping multiple points; debounce 200ms or only fire on tap-stop.
- [ ] Network offline → straight-line fallback + persistent "Offline" indicator on the editor; user can still place waypoints, snap happens later when online (or never, depending on edit-on-save semantics — pick one and stick to it).

## Dependencies
- Mapbox Directions API (free tier: 100k requests/month — far more than this project will use).
- Existing `EXPO_PUBLIC_MAPBOX_TOKEN`.
- Existing `WaypointDraft` type, `useRouteStore`.

## Notes
- This is OTA-deliverable.
- Sample request:
  ```
  https://api.mapbox.com/directions/v5/mapbox/walking/174.7762,-41.2865;174.7800,-41.2900?geometries=geojson&overview=full&access_token=<TOKEN>
  ```
- Response includes `routes[0].geometry.coordinates` (lng/lat pairs) and `routes[0].distance` (metres).
- Edge cases to handle: A and B are the same point, A is on water, B is unreachable by walking, network timeout.
- Consider: maybe only call the API when the user lifts their finger after a long-press on the destination — keeps the "tap = literal point" mental model for advanced users who want exact control.
