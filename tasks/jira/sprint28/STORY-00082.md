# STORY-00082: RunningScreen — token colors + stronger route card selection feedback

**Epic**: E-006 UI/UX
**Sprint**: Sprint 28
**Sprint Goal**: Eliminate hardcoded values, improve input/selection feedback, standardize overlays
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user selecting a running route before starting, I want a clear visual indication of which route is selected. Also, all hardcoded dark screen colors should use tokens.

## Expected Result
Running screen uses token colors for dark background/text. Selected route card shows both colored left border AND a subtle background tint, making selection state obvious at a glance.

## Acceptance Criteria
- [ ] Running screen dark background (`'#0a1a0a'`) replaced with `Colors.runningBg` token (depends on STORY-00080)
- [ ] Running screen light text (`'#e8f5e8'`) replaced with `Colors.runningText` token
- [ ] Running screen divider (`'rgba(255,255,255,0.2)'`) replaced with `Colors.runningBorder` token or inline constant
- [ ] Selected route card: left border changes to `Colors.running` (3px, blue) AND background tints to `Colors.runningLight` (`rgba(61,122,181,0.08)`)
- [ ] Unselected route card: transparent background, no accent border (unchanged)
- [ ] The checkmark badge in selected state remains (unchanged from Sprint 24)
- [ ] Visual change is immediately obvious when switching between route options
- [ ] Zero new console errors

## Dependencies
- Blocked by: STORY-00080 (needs `Colors.runningBg`, `Colors.runningText`)

## Notes
Sprint 24 added checkmark + left-border selection indicator but the background tint was missing. Selection feels ambiguous on casual scan. Background tint is the same pattern HomeScreen uses for active state.
