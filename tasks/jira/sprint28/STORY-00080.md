# STORY-00080: tokens.ts — add missing color variants + pre-computed gradient pairs

**Epic**: E-006 UI/UX
**Sprint**: Sprint 28
**Sprint Goal**: Eliminate hardcoded values, improve input/selection feedback, standardize overlays
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a developer maintaining the app, I want all color variants pre-computed in tokens.ts so that screens never need to use `.replace()` string manipulation on color values.

## Expected Result
tokens.ts exports `Colors.primaryDark`, `Colors.primaryMuted`, gradient pairs for badge rendering, and running screen color tokens. All `.replace('0.15', '0.X')` calls eliminated from all screens.

## Acceptance Criteria
- [ ] `Colors.primaryDark` added (darker primary for logo/stone accents)
- [ ] `Colors.primaryMuted` added (semi-transparent primary for borders/dividers, e.g. `rgba(93,124,70,0.4)`)
- [ ] `Colors.primaryDim` added (lighter overlay, e.g. `rgba(93,124,70,0.20)` for topo ring layer 2)
- [ ] `Colors.primaryDeep` added (deepest topo ring, e.g. `rgba(93,124,70,0.30)`)
- [ ] `Colors.runningBg` added (`'#0a1a0a'` — locked dark running screen background)
- [ ] `Colors.runningText` added (`'#e8f5e8'` — running screen light text)
- [ ] `Colors.night` added (`'#5a4fcf'` — night mode toggle icon color in Settings)
- [ ] All `.replace('0.15', '0.X')` usages in HikingScreen, HomeScreen, FriendsScreen replaced with the new tokens
- [ ] No functional behavior changes — visual output identical before and after
- [ ] Zero new console errors

## Dependencies
- Blocks: STORY-00082 (RunningScreen uses `Colors.runningBg`, `Colors.runningText`)

## Notes
String manipulation on colors is fragile and makes token changes impossible. This Story creates the foundation other Sprint 28 stories depend on.
