# STORY-00033: Region config — geo-extensibility foundation

**Epic**: E-002 地图与导航
**Sprint**: Sprint 14
**Sprint Goal**: HikingScreen 真实 GPS + 本地标记持久化
**Points**: 2
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a developer, I need a region configuration system so that NZ is one of many supported regions and no geographic constants are hardcoded in components.

## Expected Result
- `src/config/regions.ts` defines Region interface and initial NZ region
- All region-specific constants (bounds, center, default zoom, name) come from this config
- `getCurrentRegion()` utility returns the active region (default: NZ for now)
- Any component needing region info imports from config, never hardcodes

## Acceptance Criteria
- [ ] `src/config/regions.ts` exists and exports `Region` interface
- [ ] `Region` interface has: `code`, `name`, `centerLat`, `centerLng`, `defaultZoom`, `boundingBox`
- [ ] NZ region defined: `{ code: 'nz', name: 'New Zealand', centerLat: -41.2865, centerLng: 174.7762, defaultZoom: 6, boundingBox: { ... } }`
- [ ] `getCurrentRegion()` exported — returns NZ by default, extensible later
- [ ] `src/utils/geo.ts` created with: `haversineM(a, b)` returning meters, `formatDistance(meters, unit)` returning localized string
- [ ] No component file contains hardcoded lat/lng or `'nz'` string literals (region code comes from config)

## Dependencies
- None (foundational)

## Notes
