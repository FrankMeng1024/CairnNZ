# STORY-00031: Marker Store — geo-extensible local marker persistence

**Epic**: E-003 标记系统
**Sprint**: Sprint 14
**Sprint Goal**: HikingScreen 真实 GPS + 本地标记持久化
**Points**: 3
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a hiker, I want my planted flags to persist in local storage so that they survive app restarts and appear on the map when I return to the same trail.

## Expected Result
- `useMarkerStore` Zustand slice with `addMarker`, `deleteMarker`, `getMarkersForRegion` actions
- Markers saved to AsyncStorage-compatible storage (localStorage on web)
- Marker type follows geo-extensible schema: `{ id, type, regionCode, lat, lng, note, authorId, createdAt, permission }`
- All existing mock marker references in HikingScreen replaced with store reads

## Acceptance Criteria
- [ ] `src/store/useMarkerStore.ts` exists with typed Marker interface
- [ ] Marker interface has `regionCode` field (not hardcoded NZ)
- [ ] `addMarker` persists to storage and updates in-memory state
- [ ] `deleteMarker` removes from storage and state
- [ ] `getMarkersForRegion(regionCode)` returns filtered markers
- [ ] HikingScreen reads markers from store, not MOCK_MARKERS
- [ ] Plant flag flow calls `addMarker` with real data
- [ ] Delete in MarkerDetailSheet calls `deleteMarker`
- [ ] After adding a marker, it appears on map immediately (no reload needed)
- [ ] Web preview: add marker → refresh page → marker still shown

## Dependencies
- None

## Notes
Storage key: `cairn_markers`. Use same storage.ts wrapper as uiMode.
regionCode default for web preview: `'nz'` (from a config constant, not hardcoded string).
