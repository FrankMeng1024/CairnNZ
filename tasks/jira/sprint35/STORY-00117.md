# STORY-00117: AuthScreen UI Polish — Button Order, Title Layout, Focus Ring, Privacy Policy

**Epic**: E-001 账号与好友 / E-006 UI/UX
**Sprint**: Sprint 35
**Sprint Goal**: Real auth foundation
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a new user, I want the auth flow to feel polished and trustworthy, so that I have confidence registering for an outdoor safety app.

## Expected Result
- Splash: "Sign In" is the primary (green) button, "Create Account" is secondary — matching industry convention (returning users > new users)
- Create Account form: Cairn icon is small and inline left of the title (not a separate section)
- Input focus ring uses border highlight only — placeholder text remains fully visible when focused
- Privacy policy section is professional and comprehensive (location data, GDPR/NZ Privacy Act language)
- Both Sign In and Create Account show Apple/Google social login options

## Acceptance Criteria
- [ ] Splash screen: "Sign In" button is first (green/primary), "Create Account" is second (outlined/secondary)
- [ ] Create Account form: small Cairn stone icon (size 0.5) appears inline-left of the "Create Account" title text on same line
- [ ] Sign In form: small icon also inline-left of "Sign In" title
- [ ] Focus state on all inputs: border color changes to primary green, but placeholder text color remains `Colors.textMuted` (not hidden or color-shifted)
- [ ] Privacy Policy expanded section contains: data types collected (location, account), purpose, retention period, user rights, NZ Privacy Act reference, deletion rights
- [ ] "Continue with Apple" button present on both login and register forms (disabled state with tooltip "Requires physical device" acceptable for web preview)
- [ ] "Continue with Google" button present on both forms (functional in Sprint 36 — shows alert "Coming in next update" for now acceptable as placeholder)
- [ ] All changes verified at 390px viewport in web preview

## Dependencies
- None (pure frontend)

Focus ring issue: current `inputFocused` style applies `borderColor: Colors.primary` which is correct. The issue may be that the label renders on top of the input. Investigate actual visual before assuming cause.
