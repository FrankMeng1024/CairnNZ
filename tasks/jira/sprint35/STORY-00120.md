# STORY-00120: Google OAuth via expo-auth-session

**Epic**: E-001 账号与好友
**Sprint**: Sprint 35
**Sprint Goal**: Real auth foundation
**Points**: 5
**Owner**: Frontend Dev
**Status**: Deferred → STORY-00122 in Sprint 36

## Description
As a user, I want to sign in with my Google account, so that I don't have to create and remember a new password.

## Expected Result
"Continue with Google" button initiates real Google OAuth flow via `expo-auth-session`. On success, backend exchanges Google token for Cairn JWT. User is logged in.

## Acceptance Criteria
- [ ] `expo-auth-session` and `expo-web-browser` installed and configured
- [ ] Google OAuth flow works in web preview (localhost:8082) and Expo Go
- [ ] Google Client IDs configured in `app.config.js` via env vars (not hardcoded)
- [ ] Backend `POST /api/auth/google` endpoint: accepts Google `id_token`, verifies with Google, creates/finds user in DB, returns Cairn JWT
- [ ] On Google auth success: user stored in DB (if new), JWT issued, app navigates to Home
- [ ] On Google auth cancel: error state cleared, user stays on auth screen
- [ ] "Continue with Apple" button shows informative disabled state: "Available on iOS device" (no stub crash)
- [ ] Google button on both Sign In and Create Account screens routes to same flow

## Dependencies
- Blocked by STORY-00118 (needs backend /api/auth/google endpoint)

## Notes
Google OAuth requires a Google Cloud Console project with OAuth 2.0 credentials. Web client ID needed for web preview. If Google Console not configured, this story can be deferred to Sprint 36 — record in STORY notes.
Apple Sign In requires Apple Developer membership + physical iOS device — defer to Sprint 36+.
