# STORY-00078: MapHistory auto-select first session on load

**Epic**: E-006 UI/UX
**Sprint**: Sprint 27
**Sprint Goal**: Polish every remaining friction point
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user opening Map History, I want to immediately see a route on the map rather than a persistent "Select a route below to view" placeholder when sessions exist.

## Expected Result
When MapHistoryScreen loads and sessions exist, the first session in the list is automatically selected and its expanded stats are shown.

## Acceptance Criteria
- [ ] When MapHistoryScreen mounts with sessions.length > 0, the first session (index 0) is auto-selected
- [ ] The first session card renders in expanded state on load (expanded stats capsule visible without user tap)
- [ ] Map area updates to reflect the selected session (placeholder text "Select a route below to view" is NOT shown when a session is auto-selected)
- [ ] User can still tap other sessions to change selection (accordion behavior unchanged)
- [ ] When sessions.length === 0, placeholder still shows as before
- [ ] Navigation away and back: auto-select resets to first session on re-mount

## Notes
Pre-existing UX friction from Sprint 25 review: MapHistoryScreen placeholder persists when sessions visible. Low friction, backlog item. Now addressing in Sprint 27.
