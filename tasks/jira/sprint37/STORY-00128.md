# STORY-00128: JWT Expiry Handling — Auto-Logout on 401

**Epic**: E-001 账号与好友
**Sprint**: Sprint 37
**Sprint Goal**: User data ownership — sessions stored per user account
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user, when my session expires, I want to be automatically returned to the Auth screen rather than experiencing silent failures.

## Expected Result
Any API call that returns 401 triggers automatic JWT clear + navigation to AuthScreen. User sees a brief "Session expired. Please sign in again." banner on the Auth screen.

## Acceptance Criteria
- [ ] `apiService.ts` (or `authService.ts`) intercepts 401 responses from any authenticated endpoint
- [ ] On 401: `clearToken()` called, `useAppStore.setUser(null)` called, `useAppStore.setIsLoggedIn(false)` called
- [ ] Navigation to AuthScreen via `nav.replace('Auth')` or equivalent root reset
- [ ] AuthScreen shows a brief "Session expired. Please sign in again." banner (dismiss after 4s or on user input)
- [ ] Token expiry is 7 days (set in `backend/src/config/jwt.js` — verify `expiresIn: '7d'`)
- [ ] Verified: manually set a short-lived token (1s expiry), wait, make any API call — confirm auto-logout flow

## Dependencies
- Depends on STORY-00125/00126 (authenticated API calls exist to test against)

## Notes
JWT `expiresIn` set in `backend/src/config/jwt.js`. Currently likely `'7d'`. Verify and document in TECH_SPEC.md.
The expiry banner is a one-time informational display — not a persistent error state.
