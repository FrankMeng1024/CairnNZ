# STORY-00126: Frontend Session Sync — Save Sessions to Backend

**Epic**: E-001 账号与好友 / E-002 路线与记录
**Sprint**: Sprint 37
**Sprint Goal**: User data ownership — sessions stored per user account
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a logged-in user, when I finish a hike or run, I want the session automatically synced to my account.

## Expected Result
When a tracking session ends and is saved locally (Zustand), if the user is logged in, the session is also posted to the backend. On next app launch, the user's sessions are loaded from the backend and merged into the local store.

## Acceptance Criteria
- [ ] `sessionService.ts` created: `syncSession(session)` calls `POST /api/sessions` with Bearer token
- [ ] `syncSession` called from HikingScreen and RunningScreen `handleStop` (after local save)
- [ ] If not logged in: local save only, no network call
- [ ] If network fails: local save succeeds, sync failure logged but no user-facing error (silent fallback)
- [ ] On app launch (after hydrate): if logged in, `GET /api/sessions` fetched and sessions merged into local store (backend wins for same session ID, local-only sessions retained)
- [ ] `apiService.ts` utility: adds `Authorization: Bearer <token>` header automatically for authenticated requests
- [ ] Verified: complete a mock session → check backend DB for the new row

## Dependencies
- Depends on STORY-00125 (backend endpoint must exist)

## Notes
Session merge strategy: use `start_time` as dedup key. Backend session ID (`server_id`) stored alongside local ID.
Silent sync failure is intentional — offline use is a core use case (remote trails).
