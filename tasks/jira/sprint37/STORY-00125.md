# STORY-00125: Backend Session Storage

**Epic**: E-001 账号与好友 / E-002 路线与记录
**Sprint**: Sprint 37
**Sprint Goal**: User data ownership — sessions stored per user account
**Points**: 5
**Owner**: Backend Dev + DBA
**Status**: Done

## Description
As a logged-in user, I want my hiking/running sessions saved to my account, so that my data is available across devices and backed up in the cloud.

## Expected Result
Backend has a `sessions` table. `POST /api/sessions` (authenticated) stores a session record linked to the user. `GET /api/sessions` returns the user's sessions list.

## Acceptance Criteria
- [ ] `sessions` table created: `id`, `user_id` (FK → users.id), `type` (hiking|running), `start_time`, `end_time`, `distance_m`, `duration_s`, `route_points` (JSON), `flags` (JSON), `created_at`
- [ ] `POST /api/sessions` (requires Bearer token): validates required fields, stores session, returns `{session: {id, ...}}`
- [ ] `GET /api/sessions` (requires Bearer token): returns `[{id, type, start_time, end_time, distance_m, duration_s, created_at}]` for the authenticated user (no route_points in list — bandwidth)
- [ ] `GET /api/sessions/:id` (requires Bearer token): returns full session including route_points and flags
- [ ] Validation: `type` must be 'hiking' or 'running', `start_time` required ISO date, `distance_m` non-negative number
- [ ] Authorization: user can only access their own sessions (401/403 for others)
- [ ] All endpoints return `{error: "..."}` on failure (consistent with auth.js pattern)
- [ ] Verified against remote MySQL

## Dependencies
- Blocked by STORY-00121 (backend + MySQL running) — DONE

## Notes
`route_points` stored as JSON array: `[{lat, lng, timestamp}]`. Maximum ~5000 points (≈2.5h at 2s intervals). 
Flags stored as JSON: `[{lat, lng, note, timestamp}]`.
