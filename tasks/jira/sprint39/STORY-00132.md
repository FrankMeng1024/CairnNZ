# STORY-00132: Auth UX Unification — Social Buttons + Loading State

**Epic**: E-001 账号与好友
**Sprint**: Sprint 39
**Sprint Goal**: Auth UX excellence + user data isolation + premium splash animation
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user, I want the Google/Apple login buttons to appear on both Sign In and Create Account screens identically, and see immediate feedback when I tap Google so I know the app responded.

## Expected Result
- Both Sign In and Create Account screens show Google + Apple social buttons (identical layout, no difference)
- Tapping "Continue with Google" immediately shows a loading spinner on the button before the OAuth popup opens
- After OAuth success: button stays loading until backend responds and navigation fires
- After OAuth failure: button returns to normal state with inline error

## Acceptance Criteria
- [ ] "Continue with Google" button renders identically on Sign In and Create Account screens
- [ ] "Continue with Apple" button renders identically on both screens
- [ ] Tapping "Continue with Google" instantly disables the button and shows ActivityIndicator inside it (< 100ms)
- [ ] Loading state persists until `loginWithGoogle()` resolves (success or error)
- [ ] On success: navigates to Home (loading state never shown again)
- [ ] On error: button returns to normal, error message shown inline above social buttons
- [ ] No visual difference between Sign In and Create Account social sections

## Notes
Currently `handleGoogleAuth` calls `promptGoogleAsync()` with no loading state. Need to set `loading=true` immediately on tap, before the popup opens. Use a separate `googleLoading` state (not the main form `loading`) to avoid disabling the form submit button simultaneously.
