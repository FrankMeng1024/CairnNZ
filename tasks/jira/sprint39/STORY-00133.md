# STORY-00133: Form UX Polish — Validation Timing + Error Display

**Epic**: E-001 账号与好友
**Sprint**: Sprint 39
**Sprint Goal**: Auth UX excellence + user data isolation + premium splash animation
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user filling in email/password, I should not see error messages while I'm still typing or haven't submitted yet. Errors should only appear after I tap the submit button.

## Expected Result
- No validation errors shown on blur of empty fields (only on submit)
- After first submit attempt, inline validation updates on each keystroke (so user sees errors clearing as they fix them)
- Error text is compact, clear, displayed directly under the field with no layout shift
- Focus state: border turns primary green only, background stays white (no overlay)

## Acceptance Criteria
- [ ] Typing in email field and tabbing away (blur) does NOT show "Email is required" if field is empty
- [ ] Tapping Sign In / Create Account with empty fields DOES show validation errors inline under each field
- [ ] After first failed submit: editing email field clears its error in real-time as user types valid value
- [ ] Password field: blur on empty field does NOT show error
- [ ] Focus ring: only border color changes to primary green, background unchanged, placeholder text fully visible (no overlay)
- [ ] Error text font size ≤ 12px, red, sits directly below the input with 3px gap — no banner or card wrapping for field errors
- [ ] API error (wrong password etc.) shown as compact banner above the submit button, not a modal

## Notes
Root cause: `onBlur` handlers on email/password currently call `validateEmail`/`validatePassword` unconditionally. Fix: only run blur validation after `submitAttempted` ref is true. Set `submitAttempted = true` inside `handleAuth()` before validation.
