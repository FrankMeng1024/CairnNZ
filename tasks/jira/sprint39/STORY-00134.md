# STORY-00134: User Data Isolation — Sessions Per User

**Epic**: E-001 账号与好友
**Sprint**: Sprint 39
**Sprint Goal**: Auth UX excellence + user data isolation + premium splash animation
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a logged-in user, I should only see my own sessions in MapHistory and HomeScreen — not sessions from other users who previously used the same browser.

## Expected Result
- On login: session list fetched from `GET /api/sessions` (authenticated, per-user JWT)
- On logout: local session cache cleared
- Two different users logging in on the same device/browser see their own separate sessions

## Acceptance Criteria
- [ ] After login (email or Google), `fetchSessions()` is called and result populates `useSessionStore`
- [ ] `useSessionStore.hydrate()` fetches from backend API when user is authenticated (JWT present), falls back to localStorage when no JWT
- [ ] On logout (`authService.logout()`): `useSessionStore` sessions cleared to `[]`
- [ ] MapHistoryScreen shows only current user's sessions
- [ ] HomeScreen QuickStats reflect only current user's sessions
- [ ] User A logs in → sees their sessions → logs out → User B logs in → sees only User B's sessions (not User A's)
- [ ] Offline fallback: if `fetchSessions()` fails (network error), gracefully show empty state with "Could not load sessions" message rather than crashing

## Notes
`sessionService.fetchSessions()` already exists and works. Need to:
1. Call it from `useAppStore.hydrate()` after JWT is confirmed valid (after `getMe()` succeeds)
2. Store result in `useSessionStore` (replace localStorage load)
3. In `useAppStore` logout action: call `useSessionStore.setState({ sessions: [] })`
4. Update `api.ts` port back to 3001 once old Windows process confirmed dead (currently 3002 as workaround)
