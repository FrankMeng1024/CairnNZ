# STORY-00201: Eliminate session lifecycle crashes

**Epic**: Sprint 55 Hotfix
**Sprint**: Sprint 55
**Points**: 2
**Owner**: Frontend Dev
**Status**: In Progress

## Description
As a real user, when I sign out, sign in again, or finish a run, the app must not crash. Three known crash paths: (1) Sign Out tap → app crashes because of `window.confirm` not existing on RN; (2) Login screen sometimes crashes due to AnimatedCairn interval leak after unmount; (3) Run Complete has no Back button so user is stuck.

## Acceptance Criteria
- [ ] AC1: Sign Out tap on iPhone shows confirm dialog (RN Alert.alert), confirm → returns to Auth splash without crash
- [ ] AC2: Sign Out → Sign In immediately → does not crash, no white screen
- [ ] AC3: Run Complete header has visible Back button that returns user to previous screen
- [ ] AC4: AnimatedCairn intervals all cleaned up on unmount (no setStoneY-after-unmount warnings)
- [ ] AC5 (test): Jest test for SettingsScreen confirm dispatch path uses Platform.OS branch
- [ ] AC6 (test): Jest test for AnimatedCairn unmount timer cleanup
- [ ] AC7: Multiple Arch subagent reviews confirm no regression

## Notes
**Root causes**:
- `SettingsScreen.tsx:433` — `typeof window !== 'undefined' && typeof window.confirm === 'function'` is TRUE on RN (RN polyfills `window`) but `window.confirm` is undefined → calling it crashes the app
- `AuthScreen.tsx` AnimatedCairn `setInterval` for stone-rise (~line 148) is not tracked in a ref array, so unmount during animation leaves intervals running and causes setState-after-unmount errors that under some race can crash the bundle
- `RunningScreen.tsx:188` (Run Complete header) has empty `<View style={{ width: 60 }} />` placeholder where Back button should be

**Files to modify**:
- `app/src/screens/SettingsScreen.tsx`
- `app/src/screens/AuthScreen.tsx`
- `app/src/screens/RunningScreen.tsx`
