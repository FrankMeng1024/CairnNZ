# STORY-00534: Hide-from-me flow + client-side cache wipe

**Epic**: E-Friend (Friend System v1)
**Sprint**: Sprint 68
**Sprint Goal**: Land the Mark surface for Friend System v1.
**Points**: 3
**Owner**: Frontend
**Status**: Todo

## Description

When a viewer hides someone else's mark (Sprint 67 STORY-00528 `POST /api/hide`), the client must also evict the mark from any local cache so it disappears immediately without waiting for the next pull-on-focus refresh.

## Expected Result

After hide:
1. `POST /api/hide` succeeds (Sprint 67 endpoint).
2. The mark is removed from `useMarkerStore` (in-memory).
3. The mark is removed from any persisted markers cache (AsyncStorage / `mmkv` — whichever Cairn uses).
4. The mark is removed from the open map render immediately.
5. Next `GET /api/circle/markers` will also exclude it (Sprint 67 LEFT JOIN already filters), so re-hydration stays consistent.

## Acceptance Criteria

- [ ] After successful hide:
  - useMarkerStore item with that id is gone
  - Persisted markers cache no longer contains the item (verify by reading storage directly)
  - Map render frame after the hide does not show the icon
- [ ] If the user kills + reopens the app, the hidden mark stays hidden (because the server filters it out)
- [ ] If the user un-subscribes from the friend whose mark was hidden → the row in `hidden_items` stays (it's a personal blacklist; subscription state is orthogonal). Re-subscribing later → mark stays hidden (Sprint 67 backend filter still excludes it).
- [ ] Concurrent hide of 2 marks within the same session: both vanish; no race condition on the store
- [ ] If `POST /api/hide` fails → mark stays visible + error toast "Could not hide — try again."
- [ ] UX AC: hide confirm modal copy (Story-533) is the only place this action is described — the act itself is silent (no success toast, just the mark vanishing)
- [ ] No regression: hiding a mark does NOT affect the mark for any other user (server only writes to hidden_items, no UPDATE to markers table — verified by Sprint 67 hide.js code review)
- [ ] V3 review §4.2 binding satisfied: "client-side useMarkerStore 主动 wipe" (active wipe, not just server filter)
