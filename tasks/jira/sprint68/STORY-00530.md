# STORY-00530: Mark create UI — visibility toggle (default Friend)

**Epic**: E-Friend (Friend System v1)
**Sprint**: Sprint 68
**Sprint Goal**: Land the Mark surface for Friend System v1.
**Points**: 3
**Owner**: Frontend
**Status**: Done

## Description

As a Cairn user creating a mark, I want to choose who can see it — **Personal** (only me) or **Friend** (my friends + me) — with **Friend** as the default. Public is **not** offered in v1 UI per v4 §11.

## Expected Result

Mark create sheet shows a segmented toggle "🔒 Personal | 👥 Friend"; the default selection is Friend. Tapping save POSTs with `permission` ∈ ('personal'|'friend'); the backend normalizes 'friend' → DB 'group' per Sprint 67 permission.js. No 'public' option ever surfaces.

## Acceptance Criteria

- [ ] Mark create UI has segmented control with exactly 2 options: 🔒 Personal | 👥 Friend
- [ ] Default selection is **Friend** (v4.U binding — Friend is the "social default")
- [ ] Selected value persists in component state until submit
- [ ] POST /api/markers body includes `permission` from the toggle ('personal'|'friend')
- [ ] No code path in the create UI exposes 'public' (Sprint 67 H1 also rejects server-side, but UI must not even surface it)
- [ ] Tier label uses the locked icons: 🔒 / 👥 (matches Detail Sheet header in Story-532)
- [ ] Visual style matches existing Cairn sepia + Liquid Glass tokens — no new color palette
- [ ] UX AC: a first-time user understands the difference in < 2 seconds (toggle copy carries the explanation, no tooltip needed)
- [ ] All target viewports per `TECH_SPEC.md §viewports` render the toggle without truncation

## Dependencies

- Blocks: STORY-00532 (Detail Sheet header reads `permission`)
- Depends on: Sprint 67 STORY-00528 (POST /api/markers accepts permission)

## Notes

- v4 §11 forbids Public in v1 UI. Backend rejects POST permission='public' per Sprint 67 STORY-00528 (H1) — this is defense in depth: the UI never offers it, AND server rejects it.
- Existing create flows live in marker-create components (plant flow / map flow). Both must adopt the toggle.
