# STORY-00533: Like/Report UI fake + Delete dual-semantic

**Epic**: E-Friend (Friend System v1)
**Sprint**: Sprint 68
**Sprint Goal**: Land the Mark surface for Friend System v1.
**Points**: 3
**Owner**: Frontend
**Status**: Done

## Description

Wire the Like / Report / Delete buttons in Form A and Form B of the Detail Sheet (Story-532). v1 binding: **Like and Report send NO HTTP** — session-local state only. **Delete** has two semantics by creator.

## Expected Result

- Tap ❤ on a visited mark (mine or other) → button fills red, count increments locally, persists for this session only. Restart → reverts. **No DB write, no API call.**
- Tap 🚩 → toast "Thank you for reporting" 2s. **No HTTP.**
- Tap Delete on my own mark → confirm modal → `DELETE /api/markers/:id` (existing endpoint) + remove from local cache.
- Tap Delete (from-view) on someone else's mark → confirm modal with strong copy "Hidden permanently from your view" → `POST /api/hide` (Sprint 67 STORY-00528 endpoint) + remove from local cache (cache wipe in Story-534).

## Acceptance Criteria

- [ ] Like button: tap toggles state in `useMarkLikeStore` (new, session-only — DO NOT persist to AsyncStorage)
- [ ] Like count rendered = `mark.helpful_count + (session_liked ? 1 : 0)` — visual increment only
- [ ] Cold restart of app → like state gone, button restored
- [ ] Report button: tap → fire toast 2s → close — that's it
- [ ] **Zero HTTP requests** generated by Like or Report — verified by Chrome DevTools `list_network_requests` during interaction
- [ ] Delete dual-semantic:
  - Own mark → `DELETE /api/markers/:id`, on 200 remove from useMarkerStore, close sheet
  - Other mark → `POST /api/hide` with `{ item_type: 'mark', item_id: mark.id }`, on 201/200 remove from useMarkerStore (Story-534 wipes the cache deeper)
- [ ] Confirm modal copy differs by semantic:
  - Own: "Delete this mark? This cannot be undone."
  - Other: "Hide this mark permanently? You won't see it again on your map. (Other users still see it.)"
- [ ] Failure path: if DELETE or hide returns non-2xx, show toast + keep mark visible
- [ ] UX AC: confirm modal is dismissible by tap-outside (consistent with existing Cairn modal patterns)
- [ ] No regression to existing real-API Like in `MarkerDetailScreen` for v1.1 community marks (those still use `POST /api/markers/:id/vote`). v1 friend-system marks use the fake path; live community marks keep their existing wire. The Detail Sheet rendered for Story-532 is a NEW component; legacy `MarkerDetailScreen` remains for the community flow until v1.1 unifies them.
