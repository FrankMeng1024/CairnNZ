# STORY-00553: 后台 GPS 采样降频框架

**Epic**: E-Tracking · **Sprint**: 72 · **Points**: 3 · **Owner**: Frontend · **Status**: Done

## Description
As a hiker whose phone is in their pocket (screen off, app in background), I want the GPS sampling to slow down enough to save meaningful battery — but not so much that my track quality visibly drops.

## 现状根因
`app/src/utils/geo.ts:269-277` `getSamplingInterval` 只看 movement + battery<20%，**不看 AppState**。后台 running 仍是 500ms → 一小时 7200 点 → 电耗 subagent 估算 10-15%/小时。

## 改动
1. `getSamplingInterval(movement, batteryLow, appState, batteryLevel, isCharging)` 增加参数:
   ```ts
   export const BG_SAMPLING = {
     RUNNING_MS: 1000,   // 前台 500，后台降 1000（保守，不切内道）
     WALKING_MS: 3000,   // 前台 1000，后台降 3000（保守，zigzag 仍可辨）
     STATIC_MS: 15000,   // 前台 10000，后台放到 15000
     BATTERY_HIGH_THRESHOLD: 0.5,  // >50% 保持前台频率
   };
   
   export function getSamplingInterval(
     movement, batteryLow = false,
     opts?: { appState?: 'active'|'background'|'inactive'; batteryLevel?: number; isCharging?: boolean }
   ) {
     if (batteryLow) return 2000; // 现有 <20% 逻辑不变
     const inBackground = opts?.appState === 'background' || opts?.appState === 'inactive';
     const shouldDowngrade = inBackground 
       && !opts?.isCharging 
       && (opts?.batteryLevel ?? 1) < BG_SAMPLING.BATTERY_HIGH_THRESHOLD;
     if (shouldDowngrade) {
       switch (movement) {
         case 'static': return BG_SAMPLING.STATIC_MS;
         case 'walking': return BG_SAMPLING.WALKING_MS;
         case 'running': return BG_SAMPLING.RUNNING_MS;
       }
     }
     // 前台或电量充足或充电中 → 原前台频率
     switch (movement) {
       case 'static': return 10000;
       case 'walking': return 1000;
       case 'running': return 500;
     }
   }
   ```
2. `useTrackingStore` 现有 `dynamicSamplingInterval`（10s 一次重算）调用时传入 AppState + battery info
3. AppState 从 background→active 或反之 → 立即触发一次采样间隔重算（不等下一个 10s tick）
