# STORY-00100: Char counter inline truncation explanation

**Epic**: E-006 UI/UX
**Sprint**: Sprint 32
**Sprint Goal**: UI polish — pending items from Sprint 28-31 retros
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a user typing a note in CreateMarkerSheet or FlagPlantSheet, I want to see a brief inline label ("Max 30 chars") near the input when I approach or hit the limit, so I understand why my text stops being accepted.

## Expected Result
Both CreateMarkerSheet and FlagPlantSheet note inputs show a static "Max 30 chars" caption below the input (in caption/muted style) at all times, so first-time users understand the constraint before hitting it.

## Acceptance Criteria
- [ ] CreateMarkerSheet note input has static "Max 30 chars" label below the input field (caption size, muted color)
- [ ] FlagPlantSheet note input has the same "Max 30 chars" label
- [ ] Label does not overlap with the char counter (counter is right-aligned, label is left-aligned, or label replaces the empty left side of the counter row)
- [ ] Label visible at all times (not only when approaching limit)

## Dependencies
- None

## Notes
Pending from Sprint 31 retro: "CreateMarkerSheet char counter truncates input at 30 without inline explanation. First-time user may not understand why text was cut."
