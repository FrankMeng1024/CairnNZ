# STORY-00086: Create Account screen — input focus states + form field parity

**Epic**: E-006 UI/UX
**Sprint**: Sprint 29
**Sprint Goal**: Eliminate remaining hardcoded color values, complete Auth form polish, and upgrade RoutesScreen empty state
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a new user creating an account, I want the same high-quality input focus feedback I see on the Sign In form — green border + icon tint on tap — so the experience is consistent throughout the Auth flow.

## Expected Result
Create Account form fields (Name, Email, Password, Confirm Password) all show green border + green icon tint when focused, grey when unfocused, red on error. Identical behavior to Sign In form (STORY-00081).

## Acceptance Criteria
- [ ] Name field: green border + green user icon on focus; grey unfocused
- [ ] Email field: green border + green mail icon on focus; grey unfocused
- [ ] Password field: green border + green lock icon on focus; grey unfocused
- [ ] Confirm Password field: green border + green lock icon on focus; grey unfocused
- [ ] Error state (red border) overrides focus state correctly for each field
- [ ] Focused vs unfocused distinction is visually immediate (no delay)
- [ ] Zero new console errors

## Dependencies
- Follows pattern from STORY-00081 (Sign In focus states)

## Notes
STORY-00081 only instrumented Sign In form. Create Account form uses the same input components but focus state was not explicitly verified.
