## Description

As Cairn DevOps, I need to set up a weekly cron job that cleans up orphan rows in `hidden_items` (where the referenced mark/route has been deleted), since `hidden_items` doesn't have FK on `item_id` (intentional design per v4 plan §6).

## Expected Result

`node-cron` registered in `backend/src/index.js` runs every Sunday 3am cleaning orphans. `TECH_SPEC.md` has `§cron` documenting decision. Runs log to `backend/logs/cron.log`.

## Acceptance Criteria

- [ ] Decide cron runtime: in-process node-cron (recommended for simplicity) vs sidecar
- [ ] Add `node-cron` package to `backend/package.json` if not present
- [ ] Implement `backend/src/cron/cleanHiddenItemsOrphans.js`:
  - SELECT item_id FROM hidden_items WHERE item_type='mark' AND item_id NOT IN (SELECT id FROM markers)
  - DELETE in batch (LIMIT 1000)
  - Same for item_type='route'
  - Log count cleaned
- [ ] Register cron in `backend/src/index.js` startup: `cron.schedule('0 3 * * 0', cleanHiddenItemsOrphans)` (Sunday 3am UTC)
- [ ] Add monitoring: if cron throws, log to `errors.md`-equivalent + console.error
- [ ] Update `docs/TECH_SPEC.md` §cron section: documents the cron job, schedule, what it cleans, where logs live
- [ ] Manual test: insert 5 orphan rows, manually invoke `cleanHiddenItemsOrphans()`, verify deletion + log
