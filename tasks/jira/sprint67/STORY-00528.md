## Description

As Cairn backend engineer, I need to implement 8 new endpoints for Friend System v1: Memory subscriptions, circle (markers/routes/fog UNION), public marks bbox query, and hide-from-view. Plus harden POST/PATCH on markers + routes to reject `permission='public'` from client.

## Expected Result

8 new endpoints live, contract-tested, return correct data per v4 plan §7. 4 "public rejection" contract tests pass.

## Acceptance Criteria

- [ ] `POST /api/memory-subscriptions` body `{friend_id}` — triggers DB cap check + friend-must-be-friend check; returns 201 or 409 (cap) or 403 (not friend)
- [ ] `DELETE /api/memory-subscriptions/:friend_id` — removes subscription
- [ ] `GET /api/memory-subscriptions` — returns my subscribed friends list
- [ ] `GET /api/circle/markers` — returns UNION of subscribed friends' Friend+Public markers (LEFT JOIN hidden_items, filter where viewer has hidden it)
- [ ] `GET /api/circle/routes` — same for routes
- [ ] `GET /api/circle/fog` — server-side polygon UNION of subscribed friends' memory_points (or precomputed fog geometry)
- [ ] `GET /api/markers/public?bbox=lat1,lng1,lat2,lng2` — strangers' public marks in bbox, ORDER BY created_at DESC LIMIT 50
- [ ] `POST /api/hide` body `{item_type, item_id}` — INSERT IGNORE INTO hidden_items
- [ ] **v4 H1 enforcement**: POST /api/markers + PATCH /api/markers/:id reject `permission='public'` → 400
- [ ] **v4 H1 enforcement**: POST /api/routes + PATCH /api/routes/:id reject `permission='public'` → 400
- [ ] All 4 "public rejection" cases have explicit contract tests
- [ ] All endpoints use `backend/src/constants/permission.js` for ENUM values
