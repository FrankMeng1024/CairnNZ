# STORY-00124: Backend Input Validation + Error Message Quality

**Epic**: E-001 账号与好友
**Sprint**: Sprint 36
**Sprint Goal**: Live auth — MySQL running, real register/login E2E working, Google OAuth wired
**Points**: 3
**Owner**: Backend Dev
**Status**: Done

## Description
As a user, I want clear, actionable error messages when my input is invalid, so that I know exactly what to fix.

## Expected Result
Backend validates all inputs and returns specific error messages that the frontend displays inline. Frontend shows field-level errors (not just top-level banner) for validation failures.

## Acceptance Criteria
- [ ] `POST /api/auth/register` validates: name (required, 1-50 chars), email (valid format), password (min 8 chars)
- [ ] Validation errors return 400 with `{error: "<specific message>"}` — e.g. "Password must be at least 8 characters"
- [ ] `POST /api/auth/login` validates: email (required), password (required) — returns 400 for missing fields
- [ ] Frontend: validation errors from backend displayed inline below the relevant field (not just top-banner)
- [ ] Frontend: password min length hint shown below password field ("Minimum 8 characters") before submit
- [ ] Frontend: email format validated client-side before submit (prevents unnecessary API calls)
- [ ] All error states verified at 390px

## Dependencies
- Blocked by STORY-00121 (needs running backend for live error testing)

## Notes
Current backend may lack input validation beyond what's in the DB schema. This Story adds explicit validation middleware.
Frontend field-level errors complement the existing top-level error banner.
