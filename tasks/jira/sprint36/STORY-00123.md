# STORY-00123: Auth UX Polish — Remove Privacy Checkbox from Sign In + Post-Auth Landing

**Epic**: E-001 账号与好友 / E-006 UI/UX
**Sprint**: Sprint 36
**Sprint Goal**: Live auth — MySQL running, real register/login E2E working, Google OAuth wired
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a returning user, I want to sign in without re-accepting the privacy policy every time, so that the sign-in flow feels fast and frictionless. And as a newly registered user, I want to be welcomed properly after registration.

## Expected Result
Sign In form has no privacy checkbox (removed). Create Account form retains privacy checkbox. Post-registration shows a brief welcome state before navigating to Home.

## Acceptance Criteria
- [ ] Sign In form: privacy checkbox and "Please agree to continue" validation removed
- [ ] Sign In form: submit validates only email + password fields (not privacy)
- [ ] Create Account form: privacy checkbox retained (first-time registration only)
- [ ] Post-successful-registration: brief "Welcome, [name]!" feedback before Home navigation (toast, banner, or animated transition — consistent with app design language)
- [ ] Post-successful-login: no extra screen — navigate directly to Home (returning user expectation)
- [ ] Error banner wording changed: "Cannot reach server. Check your connection." → "Unable to connect. Please try again."
- [ ] All changes verified at 390px viewport

## Dependencies
- None (pure frontend, can proceed without backend running)

## Notes
Privacy Policy on Sign In is a UX friction item flagged by UX subagent Sprint 35 (Medium severity).
Post-auth welcome state addresses the UX gap: what does user see immediately after creating an account?
