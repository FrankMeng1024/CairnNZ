# Cairn 算法核心思想（v5 + 偏远保护）

> 这是**算法思想文档**，不涉及具体实现。如果思想完整，任何 case 都能推算出合理判定。

---

## 一、产品现实（不可改变的约束）

1. **NZ 步道社区 app** - 用户在地图上标 mark（标记），类型有 danger/supply/junction/scenic/cairn
2. **必须物理到场才能赞/举报** - GPS 验证，无远程操作
3. **无照片、无评论、无申诉** - 只有点赞、举报（固定理由列表）
4. **一人一 mark 只能赞或举报一种** - 互斥
5. **流量 = 用户打开 AR 看到 mark 的次数**（viewCount），不是路过
6. **DEAD 不可复活** - 用户必须新建
7. **没有作者身份认证系统** - authorRole 由平台事后判定

## 二、算法核心使命

**对路过但还没互动的陌生人，决定这个 mark 该不该展示？**

- 对已互动用户（赞/举报过）→ UI 层处理（个人化展示）
- 对陌生人 → 算法决定

## 三、三大思想支柱

### 支柱 1：趋势驱动（不是静态判定）

**核心**：人类对一个地方的评价是基于"趋势"，不是"分数"。

> "听说最近不行了" → 先观望
> "我去看了下还行" → 改变看法
> 不会因为一阵差评就永久写死它

**具体逻辑**：
- 多个时间窗口对比（30 天 / 90 天 / 全期）
- 关键看**近期 vs 远期的差异**：
  - 历史好 + 近期差 = 急转向下
  - 历史差 + 近期好 = 翻身
  - 一直好 = 稳定健康
  - 一直差 = 稳定低质
- 趋势 > 单次事件
- 动量 > 短期波动

**重要原则**：
- 不写死阈值（"5 个赞才算共识"这种是错的）
- 一个趋势波不能定生死，要看持续性
- 算法基于"已观察到的用户行为"判，不预测未来

### 支柱 2：医院模型（生命周期）

**核心**：mark 不是"活/死"二元，而是有完整生命周期，**像病人一样可救可治**。

**状态机**：

```
HEALTHY (健康, 全展示)
    ↓ 出现征兆（趋势下行 / 死寂 / 反转）
SUSPICIOUS (救命期, 曝光不变, 30 天观察)
    ↓ 趋势继续向死
CRITICAL (病危, 曝光渐降)
    ↓ 持续恶化, 进入心跳末期
HEARTBEAT (心跳, 5% 曝光)
    ↓ 仍无强心剂
DEAD (死亡, 0 曝光, 不可复活)

任何阶段强心剂（新一波正向）→ 回 SUSPICIOUS（再观察）
```

**关键规则**：
- **救命期曝光不降低** - 需要更多新用户来救/判
- **病危才开始降曝光** - 趋势确实向死
- **心跳 = 病危末期 5% 曝光** - 给最后被发现的机会
- **DEAD 不可逆** - 死了就是死了，唯一复活手段是用户新建
- **回退路径** - 算法看到新一波好评信号自动从 CRITICAL 回 SUSPICIOUS（不是从 DEAD）

**进入救命期的触发条件**：
- 急转：历史正向 + 近期负向
- 死寂过期：累积过 10 但近期长时间无新互动
- 持续衰退：多窗口对比反转
- 近期举报为主
- 量级反转：累积量大但比例偏负
- Brigade 攻击疑似：历史强正向 + 近期突然集中举报
- 持续争议：累积量足够但比例接近 1:1

### 支柱 3：偏远保护（流量分级）

**核心**：**没人去 ≠ 病症**。在 NZ 步道场景下，偏远/季节性 mark 的"零互动"是常态，不该被算法当成衰退。

**问题来源**：
- 冬季封山步道 5-9 月 0 互动 = 正常
- 偏远 hut 月流量 1 人 = 正常
- 小众路线（如 Five Passes）一年 40 人走 = 正常
- 这些 mark 应"正常寿命流失"（base × ageDecay 缓慢衰减）

**保护原则**：
- 流量低的 mark 应有寿命加成（续命机会少）
- 流量高的 mark base 寿命就够（续命机会多）
- "死寂触发救命期"逻辑只适用于历史活跃但近期突然没人的 mark
- 偏远 mark 即便累积偏负也不该轻易判病危（信号样本太少不可靠）

**流量定义（要明确）**：
- 用 viewCount（AR 打开次数）反映真实"有多少人来过"
- 不用互动密度（likes+reports/days）—— 那是结果不是流量

## 四、思想的内在张力

### 张力 1：趋势 vs 偏远保护
- 趋势驱动告诉算法："看到反转就该警觉"
- 偏远保护告诉算法："偏远 mark 反转可能不是真反转"
- 如何调和？
  - 偏远 mark 的"反转"需要更高样本量才信
  - 偏远 mark 的"死寂"是常态不是病症

### 张力 2：医院模型 vs 现实
- 医院模型给 mark "病危 → 抢救 → 回救命期"的循环机会
- 但算法看到的只是累积信号，看不到"作者意图"或"季节循环"
- 强心剂回退条件是什么？需要多严？

### 张力 3：DEAD 不可逆 vs 误杀
- 严格 DEAD 防止僵尸 mark 复活刷流量
- 但季节性 mark 在冬季死寂中可能被误杀
- 如何防止"沉默死"？

## 五、什么是"完整的思想"

完整的思想应该能推算出**任何 case** 的合理判定：

✅ 高流量 + 持续好评 → HEALTHY  
✅ 高流量 + 持续差评 → 走向 DEAD  
✅ 历史好 + 近期突然崩 → SUSPICIOUS  
✅ 历史差 + 慢慢翻身 → SUSPICIOUS → BORDERLINE  
✅ 偏远好 mark + 长期低互动 → 正常 HEALTHY/BORDERLINE，寿命缓慢流失  
✅ 季节性 mark + 冬季封山 0 互动 → 维持原状态，等下季节  
✅ 短期活动 mark + 活动结束后死寂 → SUSPICIOUS → DEAD  
✅ 持续争议 mark（一半人赞一半人举报）→ SUSPICIOUS（让用户自行判断）  
✅ Brigade 攻击 → SUSPICIOUS  
✅ 高 view 低互动（网红打卡点）→ ？这个思想能推出来吗？  

## 六、待 challenge 的核心问题

1. **三大支柱组合能覆盖所有场景吗？**有没有 case 用这套思想推不出合理判定？
2. **支柱之间有冲突吗？**（如趋势 vs 偏远保护、医院模型 vs 偏远保护）
3. **缺少哪些维度？**（如：用户身份信号、时间循环性、文化因素、地理因素、跨 mark 行为...）
4. **现实约束（无认证 / 无申诉 / DEAD 不可逆）下，思想能否自洽？**
5. **思想有没有内置矛盾？**（例如"趋势驱动"要求看变化，但"偏远保护"在没数据时无法看变化）
6. **被攻击者读懂思想后，能怎么利用？**

## 七、challenge 任务

不要 challenge 算法实现，challenge **思想是否完整**。

**任务**：提出 case 和场景，看这套思想能否推出合理判定。
- 如果能推出 → 思想 cover 了这个维度
- 如果推不出 → 思想漏了，需要补充
- 如果推出错的 → 思想有内在矛盾

**判断标准**：
- 不要 case "技术上算法做不到"（如跨 mark 分析）
- 要 case "思想上无法决定该判什么"（说明思想本身漏了）
