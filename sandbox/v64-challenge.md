# Cairn 算法思想 v6.4 — Challenge 报告

> Challenger: 严苛模式。只 challenge 思想逻辑,不评估系数/数字。

**完整度评分: 78 / 100**

v6.4 比 v6.3 更自洽(寿命优先、时钟 A 不冰冻、急转双向、严重度分层都补到位),但**仍存在 5 个 P0 / P1 级思想漏洞**。下面逐条说。

## P0-1:「向上急转 + SUSPICIOUS 强心剂回退」与「严重度只影响处理力度」之间存在路径冲突

**漏洞**:
- §三 支柱 1 写:急转识别**先看条数(或占比),不看 report 类型/严重度**。
- §三 支柱 2 写:**强心剂(向上急转)→ 回退到上一状态**。
- §五 写:**严重度参与「趋势确认后的处理力度」**——高严重度组合「更快进 CRITICAL / HEARTBEAT」。

**逻辑冲突场景**:Routeburn supply mark 收到 20 条「虚假广告」report 进 SUSPICIOUS,严重度极高,处理力度本应「加速进 CRITICAL」。同一时刻又收到 30 条新 like(向上急转条数门槛达成)→ 强心剂触发回 HEALTHY。

问题:**强心剂回退是否也按严重度加权?如果不按,那高严重度的 SUSPICIOUS 和低严重度的 SUSPICIOUS 在「治疗速度上有差异、在治愈难度上无差异」——这内部不一致**。

攻击者怎么用:对一个商业 mark 投放「虚假广告」report 后,自己再刷 30 个真实陌生人 like(物理到场成本高但不是不可能,例如付费让朋友到场)→ 强心剂秒退 HEALTHY → 严重度的「严打商业」效果被绕过。

**修补方向**:思想层须明确——**强心剂回退的门槛是否随当前 SUSPICIOUS 的严重度组合而提高**。否则「严重度只影响处理力度」实际只影响**恶化速度**,不影响**回退难度**,治疗机会的对称性被破坏。

---

## P0-2:「严重度不参与趋势识别」对「不喜欢」类型形成攻击红利

**漏洞**:
§五 明文「**1 条最严重 report 不构成趋势**」、「严重度不参与趋势识别」。这话反过来读就是:**任何严重度都得**靠条数/占比构成趋势——攻击者只要凑够条数,用什么类型都能拖进 SUSPICIOUS。

**「不喜欢」是攻击者最佳武器**,原因:
1. 严重度最低 → 处理力度最弱 → 不容易进 CRITICAL/HEARTBEAT,但**足够把 mark 推进 SUSPICIOUS**。
2. 「不喜欢」是主观意见,真实用户也会用 → IP/设备封锁、信誉权重都难以识别。
3. 进 SUSPICIOUS 即触发 UI 警告标 → **即使不杀死也已经污染 mark 的信任感**。

**攻击场景**(Case S 补充):竞争对手对自家附近的 supply mark 组织 30 个真实用户路过点「不喜欢」(理由模糊,可能就是「我不喜欢」)。条数构成趋势,无论严重度多低都进 SUSPICIOUS,mark 上挂警告标长达数周——商业目的达成。

**思想层缺口**:v6.4 只说「处理力度由严重度决定」,但**没说「进入 SUSPICIOUS 的条数门槛」是否随严重度变化**。如果门槛同一档,那「不喜欢类」性价比远高于「虚假广告类」攻击。

**修补方向**:思想层应当承认——「进 SUSPICIOUS 的条数/占比门槛」与「进 CRITICAL/HEARTBEAT 的处理力度」**都应受严重度调制**。否则严重度只在恶化阶段起作用,在入院阶段失效。

## P0-3:「向上急转门槛」与「向下急转门槛」是否对称,文档完全没说

**漏洞**:
§三 写「急转有方向:向上 / 向下都是急转」、「先看条数(或占比)」,但**没回答**:
- 向上急转的条数门槛 = 向下急转的条数门槛?
- 强心剂从 HEARTBEAT 回 SUSPICIOUS 的门槛 = 从 SUSPICIOUS 回 HEALTHY 的门槛?

**为什么是漏洞**:这是**思想关系问题,不是数字问题**。如果对称,意味着「治愈和发病难度相同」——不符合医学直觉(救命比致病难)。如果不对称,**思想必须明确「治愈门槛 ≥ 发病门槛」**否则攻击者可以用低成本治愈,把每次 SUSPICIOUS 都靠刷 like 拉回。

**攻击场景**(Case T):攻击者建一个真实 mark 长期累积良好信誉。某天对手 brigade 进 SUSPICIOUS。攻击者立刻动员 8 个真朋友物理到场点 like(他们各点自己 1 票,符合规则)→ 强心剂条数门槛若与发病门槛相同 → 立即回 HEALTHY。**这是「续命寄生」的合法版本——不是攻击,但绕过了 SUSPICIOUS 的隔离作用**。

**修补方向**:思想层须明文规定:**向上急转门槛 > 向下急转门槛**,且差距足以让 brigade 攻击的回退成本高于发起成本。具体多少由算法层定,但**关系**须在思想层固化。

## P1-4:「时钟 A 在所有状态都不冰冻」+「续命系数继续生效」+「寿命优先」三者交互边界不清

**漏洞**:
§四 写「**任何状态下,时钟 A 走完 → DEAD,无视治疗结果**」,又写「**续命在所有状态下都生效——SUSPICIOUS 中续命依然延长寿命**」。

Case J 自身就是这个机制的诠释:进 SUSPICIOUS 寿命剩 1 天 → 50 like → 续命到 30 天。

**矛盾点**:**续命系数的输入是「单位时间 like / view 转化率」**(§三 支柱 3)。在 SUSPICIOUS 状态,viewCount 仍在累积(100% 展示),like 也在累积——和 HEALTHY 状态计算续命的输入**完全相同**。

那么问题来了:
- 进 SUSPICIOUS 的 mark **本来就处于「负向急转」中**——意味着近期负向占比高。
- 但 like 还在来 → 续命系数依然生效 → 寿命延长。
- 寿命延长的同时,负向 report 也继续累积 → SUSPICIOUS 治疗机会判定可能继续恶化。

**思想缺口**:**SUSPICIOUS 状态的续命系数应不应该按「负向占比」打折?**思想没说。如果不打折,**一个明显被 brigade 的 mark 仍能因为大量 view 续命续到非常久**——这违反「医院模型」直觉(病人不该一边重病一边长寿)。

更尖锐的攻击场景(Case U):商业 mark 进 SUSPICIOUS 后,攻击者(作者团伙)立刻发动 view 流量(刷开 AR)+ 部分付费朋友到场 like → 续命系数生效 → 寿命续长 → SUSPICIOUS 期被无限拉长 → UI 警告标贴在 mark 上数月仍 100% 展示。即使最终 DEAD,商业目的早已达成。

**修补方向**:思想层须明文——**SUSPICIOUS / CRITICAL / HEARTBEAT 状态下,续命系数应受当前状态调制(衰减)**。或更狠:救命期续命系数封顶不超过基础寿命的 X(X 由算法层定,但**「救命期续命受限」**这个逻辑关系须在思想层固化)。

## P1-5:「复活 = 新 mark + 历史弱权重信誉资产」具体逻辑组成不清

**漏洞**:
§三 §六 §七 反复强调「复活 = 新 mark + 历史弱权重」,但**思想层没回答**:
1. 「弱权重」体现在哪些维度?是续命系数加成?是初始信誉?是抗 SUSPICIOUS 抗性?三者全部?
2. 多次复活后,历史资产是**叠加**还是**稀释**还是**衰减**?Case P 说「多次复活后历史资产稀释」——但**稀释机制是基于次数还是基于时间还是基于新 mark 本身的表现**?
3. **DEAD 时的状态原因**(自然老死 vs 病死 vs 寿命走完在 SUSPICIOUS 中)是否影响复活的弱权重?
   - 自然老死的 mark 复活 → 历史资产应该完整。
   - 病死(走完 HEARTBEAT)的 mark 复活 → 历史资产是否应该被惩罚?
   - 思想层没区分。

**攻击场景**(Case V):商业 mark A 被举报到 HEARTBEAT 后 DEAD。作者远程复活 → 新 mark 享受历史 4500 like 的弱权重信誉 → 续命系数初始就高 → 即使复活后真实表现差也能撑很久。**「历史好就能复活」必须区分「历史好且自然老死」和「历史曾经好但被社区否决」**,否则相当于洗白机制。

**修补方向**:思想层须明确——
- 复活时的历史弱权重应**反映 DEAD 的成因**:自然老死 = 历史完整继承;病死 = 历史打折;HEARTBEAT 死 = 历史打更狠折扣。
- 多次复活的稀释**应基于复活次数 + 上次 DEAD 的成因综合**,而非单一维度。

## 二、§九「不做的事」边界审查

§九 大体合理,但**两条边界值得重新讨论**:

1. **「不防真人小团队续命寄生」**——v6.4 接受这个边缘风险。但配合 P0-3 / P1-4 的漏洞,小团队续命寄生的成本被进一步降低(强心剂门槛不明 + 救命期续命不打折)。建议:这条「不做」**应当依赖于 P0-3 修补到位**,否则小团队续命寄生会从「边缘风险」升级为「主流攻击向量」。

2. **「不防假死复活攻击」**——配合 P1-5,如果复活的弱权重不区分 DEAD 成因,「假死复活」就不是被「稀释最终消亡」的机制压制——而是**洗白快通道**。这条「不做」**也依赖于 P1-5 修补到位**。

## 三、新增 Case 推算(补 v6.4 验证盲点)

### Case S — 「不喜欢」brigade 攻击(P0-2 验证)
30 个真实用户对竞品 mark 点「不喜欢」。条数构成趋势 → 进 SUSPICIOUS → UI 警告标即使最终不死也长期挂。**v6.4 当前思想下,这是合法可达成的**。

### Case T — 续命寄生合法版(P0-3 验证)
mark 被 brigade 进 SUSPICIOUS。作者动员 8 个真朋友物理到场 like。若强心剂门槛 = 发病门槛,立即回 HEALTHY。**SUSPICIOUS 的隔离作用被绕过**。

### Case U — SUSPICIOUS 寿命无限续(P1-4 验证)
商业 mark 进 SUSPICIOUS 后立刻刷 view + 付费朋友到场 like。续命系数生效,寿命续到上限。**警告标长期挂但 mark 不死**。

### Case V — DEAD 成因不区分的洗白(P1-5 验证)
mark 因 brigade 走完 HEARTBEAT 而 DEAD。复活后享受历史 4500 like 弱权重。**「曾经被社区否决」的事实在思想层没有被记录**。

### Case W — HEALTHY 中持续争议触发 SUSPICIOUS(Case R 补强)
§七 Case R 提到「持续争议也是触发 SUSPICIOUS 的条件之一」,但**思想正文 §三 §四 都没列**——只在 Case R 中冒出来。**这是思想内部不一致**:正文只承认「急转触发 SUSPICIOUS」+「寿命走完触发 DEAD」,「持续争议触发 SUSPICIOUS」是第三条路径,但 §三 状态机图里没画。

**修补方向**:要么思想正文增加「持续争议」作为 SUSPICIOUS 入口,要么 Case R 的处理改为「占比驱动判定持续争议为低质 → 自然衰减加速 → 自然老死」,二选一。

## 四、总评

v6.4 在框架上比 v6.3 **更稳更自洽**,「寿命优先」和「时钟 A 不冰冻」两条修补漂亮地堵了 v6.3 的两个矛盾。但**急转双向、严重度分层、复活机制**这三个新引入的概念**思想层定义还不够细**——具体表现是「关系不对称未明确」「打折机制缺失」「成因区分缺失」。

**P0 三条必修**(P0-1 强心剂回退是否按严重度调制 / P0-2 SUSPICIOUS 入口门槛是否按严重度调制 / P0-3 双向急转门槛对称性)。
**P1 两条建议修**(P1-4 救命期续命是否打折 / P1-5 复活弱权重是否按 DEAD 成因区分)。
**Case W 内部一致性**(持续争议是否是第三条 SUSPICIOUS 入口)需正文澄清。

修补到位后,完整度可达 90+。当前 78 分主要扣在「思想层留下了过多关系未定义的灰区,留给算法层的不是『定数字』而是『定关系』——这是思想职责未尽到」。
