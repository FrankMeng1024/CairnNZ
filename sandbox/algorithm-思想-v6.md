# Cairn 算法思想 v6.7 — 占比驱动 · 寿命走完即死 · 投票即治疗

> 写于 2026-06-02。基于多轮 subagent challenge + 用户产品反馈。
> **本文档为算法思想,不涉及实现细节**。如果思想完整,任何 case 都能推算出合理判定。
> **思想文档不包含任何具体数字、系数、权重值、阈值**。所有量化决策在算法层完成。
> 思想只回答「逻辑关系」,不回答「具体多少」。

---

## 一、产品现实约束(不可改变)

1. **NZ 步道社区 app**——用户在地图上标 mark(标记),类型有 danger / supply / junction / scenic / cairn
2. **必须物理到场才能赞/举报**——GPS 验证,无远程操作
3. **没图、没评论、没申诉**——只有点赞、举报(固定理由列表)
4. **一人一 mark 只能赞或举报一种**——互斥,且**永久 1 票**(不能改、不能撤)
5. **作者本人不能给自己 mark 点赞或举报**——杜绝自吹
6. **Report 分 3 大类**:
   - **虚假广告**(严重度最高)
   - **信息不符**(严重度中)
   - **不喜欢**(严重度最低)
   - 各 mark type 的具体 option 映射在产品层定义,算法层只看 3 大类
7. **流量 = 用户打开 AR 看到 mark 的次数**(viewCount)
8. **mark 不是广告投放,是物理感受**——偏远无人 view 的 mark 从地图都看不到
9. **DEAD 后可远程复活**(条件见 §六决策 1)
10. **平台层有 IP / 设备指纹封锁**——可疑设备/IP 互动**根本进不到算法**
11. **没有作者身份认证系统**
12. **Cairn 不承担安全权威职责**——只承担社区互动平台职责,DOC 等官方账号不豁免
13. **Cairn 是温暖他人的工具,不是高价值商业目标**——好人比坏人多,**算法不为复杂攻击做特殊防御**,简单对称设计即可

## 二、算法核心使命

**对路过但没互动过的陌生人,决定这个 mark 该不该展示?**

- 已互动用户 → UI 层处理(个人化展示)
- 陌生人 → 算法决定

## 三、三大思想支柱

### 支柱 1:占比驱动

**核心**:所有判定都基于**占比/比例**,而非绝对数字。

**关键原则**:
- 数字脆弱、易钻空、不适应变化
- 占比动态、适应任何流量级别和时间长度
- **算法系数应为连续函数,无跨档跳跃**

**急转识别**:
- 「急转」= 近期 sentiment 占比 vs 远期 sentiment 占比的**剧烈变化**
- **必须有量级**:1 条信号不构成趋势(一根线没有"转角度数")
- 急转有方向:**向上 / 向下都识别**,但走不同分支
- **急转识别先看条数(占比),不看 report 类型/严重度**
- **入口和回退门槛对称**——简单设计,不为复杂攻击做特殊防御

**急转后处理分支**:
- **向下急转** → 进 SUSPICIOUS(唯一 SUSPICIOUS 入口)
- **向上急转**:
  - 当前 HEALTHY → 续命系数加成
  - 当前 SUSPICIOUS / CRITICAL / HEARTBEAT → **强心剂(同时续命 + 回退,两个作用都生效)**

**重要**:**持续争议(如 50:50 长期稳定)不是 SUSPICIOUS 入口**——没急转就按正常寿命走,UI 直接展示赞反占比让用户自己判断。

**慢性恶化也不是 SUSPICIOUS 入口**——慢慢变差的 mark 通过转化率系数自动降低续命 → 寿命缩短 → 自然消退,不需要算法特殊干预。

### 信号消化(利空利好逻辑)

**核心**:信号有时间方向,**强心剂触发后,触发它的旧负向信号被"消化"降权**,后续判定只看强心剂之后的新信号。

类比股票市场:
- 利空消息出来 → 进 SUSPICIOUS
- 利好消息出来 → 强心剂触发,回 HEALTHY
- 利空被消化 → 之后市场不会因为窗口里还能看到上周的利空就再次下跌
- 但若新利空出现 → 再次进 SUSPICIOUS(走第二轮)

→ 强心剂触发后,旧 report 在后续滑动窗口判定中权重大幅降低,只看新信号方向。

→ 这避免了「来回切震荡」——回 HEALTHY 后不会立即被旧数据再次触发向下急转,但新负向信号仍能正常触发。

**具体应用**:
- "强心剂"= 向上急转的 SUSPICIOUS+ 版本
- "寿命续命"= 单位时间内 like / view 转化率
- "信号源多样性"= 独立用户数占总互动数的比例
- "流量识别"= 当前访问量占基线的比例

### 支柱 2:医院模型(双路径生命周期)

**核心**:mark 像病人,有两种死法:
- **自然老死**:寿命走完 → 直接 DEAD,不进 ICU
- **病死**:趋势急转向下 → SUSPICIOUS → 治疗失败 → CRITICAL → HEARTBEAT → DEAD

**关键认知**:**SUSPICIOUS 不是必经之路,只是趋势突变(向下)的入口**。

**状态机**:

```
HEALTHY (健康, 100% 展示)
   ├─ 寿命走完 → DEAD(自然老死)
   ├─ 向下急转 → SUSPICIOUS(唯一 SUSPICIOUS 入口)
   └─ 向上急转 → 续命系数加成,维持 HEALTHY

SUSPICIOUS (救命期, 100% 展示 + UI 警告标)
   ├─ 强心剂(向上急转,门槛对称)→ 回 HEALTHY
   ├─ 治疗机会内多数失败 → CRITICAL
   └─ 寿命走完 → DEAD(寿命优先)

CRITICAL (病危, 30% 展示)
   ├─ 强心剂 → 回 SUSPICIOUS
   ├─ 持续恶化 → HEARTBEAT
   └─ 寿命走完 → DEAD

HEARTBEAT (心跳, 5% 展示)
   ├─ 强心剂 → 回 SUSPICIOUS
   ├─ 治疗机会内仍无强心剂 → DEAD
   └─ 寿命走完 → DEAD

DEAD (死亡, 0 展示)
   ├─ 资格判断:历史信誉够 → 远程复活(复活后是新 mark)
   ├─ 资格判断:历史信誉一般 → 必须亲自到场复活
   └─ 资格判断:历史信誉差 → 不可复活,用户须新建
```

**关键规则**:
- **治疗机会 = 新陌生人投票(new like 或 new report)**
- 由于产品层「1 人 1 mark 1 票永久」,view 再多次也只产生 0 或 1 个治疗机会
- **机会消耗攻击不存在**:养号路过 view 不投票 = 0 个机会被消耗
- **没新投票 = 治疗时钟 B 完全暂停**
- **救命期长度由治疗机会的占比驱动**,而非绝对治疗机会数
- **强心剂 = 向上急转**,门槛与向下急转入口对称

### 支柱 3:流量动态系数

**核心**:所有 mark 用同一套算法。**type 决定 base 寿命**,**单位时间转化率动态调整系数**。

**关键原则**:
- type 基础寿命是起点,不是终点
- 单位时间内 like / view 转化率 → 续命系数
  - 高转化 → 寿命大幅延长
  - 低转化 → 续命少
  - 0 view 或有 view 0 vote → 寿命**正常流失**
- **续命存在渐近上限**——续命系数边际递减
- **续命系数在所有状态下都生效**(HEALTHY/SUSPICIOUS/CRITICAL/HEARTBEAT 都一样,不打折)
- **冷启动无问题**:作者不能给自己点赞,新 mark 第一个 like 必然来自陌生人

**关键创新**:用**滑动窗口 view / 滑动窗口天数**作为流量占比,**不用累积数据**。

## 四、自然衰减 vs 治疗时钟(v6.7 寿命规则)

mark 同时被两套时钟驱动:

### 时钟 A:自然衰减(0 view 慢速 + 定期续命奖励)

**核心 1:0 view 期慢速流失(冰冻原则)**
- 有 view 期:寿命按基础速度流失
- **0 view 期:寿命流失约 0.3x 速度**(不是绝对暂停,但显著减缓)
- 类比"冰冻冷藏":没人来 mark 的时候老化很慢
- 任何状态(HEALTHY/SUSPICIOUS/CRITICAL/HEARTBEAT)都适用

**核心 2:续命是定期小额奖励,不是一次性**
- 算法**每隔一段时间(如 30 天)** 评估当前表现
- 根据当前转化率(累积 like / 累积 view) → 给一小段寿命奖励(几十天量级)
- **持续好表现 → 长期累积出长寿命**(不是瞬间到顶)
- 急转向上的 like burst → 一次性少量奖励(不夸张)

**核心 3:进病期不扣寿命**
- 进 SUSPICIOUS / CRITICAL / HEARTBEAT 不削寿命
- 寿命累积保留
- **病期不再续命**(不再奖励)
- 寿命继续按时钟 A 流失(0 view 慢速)
- 后续:
  - **表现好转 → 强心剂回退 → 回 HEALTHY 后继续续命**
  - **表现继续恶化或不动 → 寿命自然走完 → 猝死(dead_sick)**

### 时钟 B:治疗时钟(仅在 SUSPICIOUS / CRITICAL / HEARTBEAT 启动)

- 进入救命期后启动
- **完全由治疗机会驱动**(new vote = 一次治疗)
- **没新投票 = 时钟 B 完全暂停**
- 治疗机会的占比决定 mark 命运

### 寿命优先的绝对规则

**任何状态下,时钟 A 走完 → DEAD,无视治疗结果**。

### 关键 case 推算(v6.7 深山 case)

mark 在 Day 1-365 大部分 0 view → 寿命慢速流失保留
Day 365 突然 10 like → 一次性少量奖励
Day 366 进 SUSPICIOUS → 不扣寿命,但不再续命
Day 366-1461 三年 0 view → 慢速流失(1095×0.3 ≈ 328 天消耗)
Day 1461 50 人 20L 30R → 60% 负向 → 继续向下
最终预测:**HEARTBEAT 或寿命走完 → dead_sick**

## 五、Reporter 信誉权重 + Report 严重度

**所有进入算法的 like/report 都被加权**,权重由**信誉 × 严重度**共同决定。

### 信誉维度(逻辑关系,不含具体权重值)

| 维度 | 信誉影响 |
|---|---|
| 注册时间短(新号) | 权重低 |
| 行为偏向(只 report 不 like) | 权重低 |
| 行为偏向(只 like 不 report) | 权重低 |
| 跨 mark 集中举报 | 权重低 |
| 行为均衡 | 权重正常 |
| 历史可信 | 权重高 |

### Report 严重度

| 类型 | 严重度 |
|---|---|
| 虚假广告 | 最高 |
| 信息不符 | 中 |
| 不喜欢 | 最低 |

### 严重度的作用范围

**严重度不参与「是否构成趋势」的判定**:
- 趋势识别先看**条数(或占比)**
- 1 条最严重 report 不构成趋势——5000 like 对 1 条「虚假广告」维持 HEALTHY
- **严重度也不参与 SUSPICIOUS 入口/回退门槛判定**——简单对称设计

**严重度参与「趋势确认后的处理力度」**:
- 同样向下急转,「虚假广告」类型的处理比「不喜欢」类型更狠
- 加速进 CRITICAL / HEARTBEAT
- 高严重度类型组合 → 更快进 DEAD
- 低严重度类型组合 → 给更多治疗机会

### 与产品层的关系

- 产品层:IP 封锁 + 设备指纹(硬封锁)
- 算法层:信誉权重 × 严重度权重(软权重)

### 已知边缘风险

精心策划的小规模钓鱼攻击仍可能成功——这是产品-算法权衡接受的边缘风险。Cairn 不为复杂攻击做特殊防御。

## 六、四个决策固化

### 决策 1:寿命优先 + DEAD 复活两层判断

**寿命规则**:
- 寿命走完 → DEAD,任何状态都适用,无视治疗结果(寿命优先)
- 时钟 A 在所有状态下都正常运转
- 时钟 B 在无新投票时完全暂停

**DEAD 复活机制**(关键修正):

**复活 = 带历史记录的 mark**:
- **历史 like / report 全部保留**(用户看不出和未死前的区别)
- **寿命 = base 寿命 + 历史荣誉寿命加成**
- 历史好评越多 → 历史加成越大 → 起跑线越长
- 后续表现继续累计到原历史里(累计数继续增长)
- 偏远参数另外算(那是流量系数,不是复活逻辑)

**复活资格判断**:
- 历史信誉够好 → 可远程复活(无需亲自到场)
- 历史信誉一般 → 必须亲自到场复活
- 历史信誉差/无 → 不可复活,用户须新建
- 具体门槛由算法层根据历史 like / report 占比、独立用户数、生命长度等综合判断
- 思想层不强制区分自然老死/病死,算法层根据历史综合判断资格

**关键洞察**:复活不是「魔法重生」,只是「继续之前的故事」。
- Tongariro 类极好 mark 复活 → 历史加成大,起跑线长,实际可永生
- 商业 mark 复活 → 历史加成小,寿命短,自然消亡
- 凭实力续命,算法自我筛选

### 决策 2:Reporter 信誉权重 × Report 严重度
- 算法层:信誉 × 严重度(软)
- 产品层:IP/设备封锁(硬)
- **严重度不影响趋势识别和入口/回退门槛,只影响趋势确认后的处理力度**

### 决策 3:占比 > 数字 + 急转双向对称
- 所有判定基于占比
- 滑动窗口而非累积
- 系数为连续函数
- 急转双向识别(向上 / 向下),**门槛对称**

### 决策 4:简单对称,不防复杂攻击
- Cairn 是温暖工具,不是高价值商业目标
- 算法不为复杂攻击做特殊防御
- 简单设计 > 防御所有边缘 case

## 七、关键 case 推算验证

### Case A:冬季封山的 DOC 雪崩警告
- 长期 likes + HEALTHY,5-9 月 0 view
- 时钟 A 正常流失(任何状态都不冰冻)
- 寿命走完 → DEAD,新一年 DOC 重发或远程复活

### Case B:偏远 mark 长期 0 互动
- HEALTHY 正常流失 → 寿命走完 DEAD
- ✅ 自然老死

### Case C:偏远 mark 突然爆火
- 滑动窗口立刻识别热门
- 转化率系数加成续命
- ✅ 算法自动适应

### Case D:偏远 mark 一来就被集中 report
- 条数构成趋势 → 向下急转 → SUSPICIOUS → CRITICAL → DEAD
- ✅ 流量加成挡不住趋势恶化

### Case E:Mt Cook 新 scenic 第 1 天 burst
- 0 互动 → 30 like 0 report
- 向上急转 + HEALTHY → 续命加成
- ✅ 维持 HEALTHY

### Case F:Tongariro 干净 mark 被 1 条「虚假广告」攻击
- 5000 like 0 report,1 条最严重 report
- 1 条不构成趋势(条数太少)
- 严重度不参与趋势识别
- ✅ 维持 HEALTHY

### Case G:Routeburn supply 真实情况变差
- 远期 200 like 2 report → 近期 20 条「资源已消失」
- 条数构成趋势 + 中严重度
- 向下急转 → SUSPICIOUS,正常处理力度
- ✅ 进入治疗

### Case H:Wanaka cairn 收到混合 report
- 6 条 report 构成趋势 → 向下急转 → SUSPICIOUS
- 类型组合中有「虚假广告」→ 处理力度比纯「不喜欢」更狠

### Case I:Mt Aspiring 寿命末期突然急转
- 寿命剩 1 天进 SUSPICIOUS,第 2 天没人来 → DEAD
- ✅ 寿命优先

### Case J:Mt Aspiring 寿命末期续命
- 寿命剩 1 天 → 50 个 like → 续命到 30 天 → 继续 SUSPICIOUS
- 30 天内没强心剂 → DEAD
- ✅ 续命有效但寿命优先

### Case K:HEARTBEAT 后切流量(伪永生)
- 时钟 A 在 HEARTBEAT 状态正常流失
- 寿命走完 → DEAD
- ✅ 不是真问题

### Case L:钓鱼攻击(养号 + 单点集中)
- 条数构成趋势 → 向下急转 → SUSPICIOUS
- 攻击者反向刷 like → 向上急转 → 回 HEALTHY
- **来回切允许**——简单对称设计
- ⚠️ 边缘风险接受

### Case M:DOC 警告被 brigade 干掉
- 算法不豁免 DOC,正常处理
- ✅ Cairn 不承担安全责任

### Case N:商业广告 mark
- 多个真实「虚假广告」report → 条数构成趋势 → SUSPICIOUS
- 「虚假广告」最高严重度 → 加速 CRITICAL → DEAD
- ✅ 严打商业 mark

### Case O:Tongariro 火山口自然老死复活
- 5 年 4500 like 50 report,寿命走完 DEAD
- 第 1 层资格:历史极好 → 可远程复活
- 第 2 层加成:历史好评多 → 复活后初始寿命 ≫ base
- ✅ 凭实力续命

### Case P:商业 mark 多次复活
- 商业 mark 朋友圈刷 like 撑命 → DEAD
- 第 1 层资格:历史一般 → 必须亲自到场复活(成本高)
- 第 2 层加成:历史好评有限 → 初始寿命 ≈ base
- 多次复活后历史资产稀释 → 最终消亡
- ✅ 不是 bug

### Case Q:Tongariro 持续真实热门
- 大量真实用户 like → 续命系数持续生效
- 渐近上限封顶
- 自然 DEAD → 远程复活继续
- ✅ 真实热门 mark 永生

### Case R:Mt Eden 持续争议(50:50)
- 没急转,占比稳定
- **不进 SUSPICIOUS**——维持 HEALTHY
- 转化率低 → 续命少 → 自然走完 DEAD
- UI 直接展示赞反占比让用户自己判
- ✅ 算法不干预持续争议

## 八、思想 v6.6 vs v6.5 的关键差异

| 维度 | v6.5 | v6.6 |
|---|---|---|
| 慢性恶化处理 | 模糊 | **不加入口,转化率系数自动处理** |
| 复活机制 | 两层判断(模糊) | **带历史记录的 mark + 寿命=base+历史加成** |
| 强心剂回退后 | 可能震荡 | **信号消化:旧 report 降权,只看新信号** |
