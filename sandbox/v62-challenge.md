# Cairn 算法思想 v6.2 — Challenge 报告

**Challenger 立场**：严苛 challenger，不客气。
**评分：78 / 100**

v6.2 在 v6.1 基础上修了 4 个 P0，但修补本身引入了**至少 2 个 P0 新漏洞**和 **3 个 P1 矛盾**。整体思想框架站得住，但「寿命走完即死」+「HEALTHY 不冰冻」组合在多个真实场景下产生硬伤。

---

## 一、修补是否真的解决了 P0？

### 1.1 「寿命走完直接 DEAD」—— **新 P0：好 mark 被强制安乐死**

§六决策 1 与 Case A、Case G 自相矛盾。

§四时钟 A 写明：「单位时间内 like / view 转化率高 → 续命系数 > 1.0，高转化好 mark 寿命远超 base」。
§六又说：「寿命走完 = 直接 DEAD，无条件」。

**矛盾点**：续命系数把寿命**延长**到什么程度算「走完」？如果转化率把寿命续到 base × 5 = 450 天，那么「base 寿命 90 天走完」根本不会触发，「寿命走完即死」就是空话；如果以 base 90 天为准，那好 mark 就被强制安乐死，续命系数白做。

思想文档没有讲清「寿命」=「base」还是「base × 续命系数累积值」。这是 P0 级别的逻辑空洞。

**Case Alpha**（新增）：Mt Cook 主道 cairn，3 年来稳定 HEALTHY，每月 50 view / 30 like，转化率 60%。按当前思想，寿命要么 90 天就被强制 DEAD（荒谬），要么续命系数让它接近永生（与「兜底防永驻」矛盾）。**思想必须二选一并写清**。

### 1.2 「HEALTHY 不冰冻」—— **解决了一半，制造了新问题**

支柱 3 说「0 view → 寿命正常流失」。这在 Case A（DOC 雪崩警告封山 5 个月）下直接判死高价值警告 mark。§七 Case A 自己也承认：「如果 mark 已运行 7 个月，封山 5 个月就到寿命了，自然 DEAD」，并把它写成「Cairn 接受的产品行为」。

**这是把设计缺陷包装成产品决策**。雪崩警告刚好在春天回来时被算法判死，下一批登山者看不到警告 = 真实人身风险。「Cairn 不承担安全责任」是法律免责声明，不是算法设计借口。

### 1.3 「Report 3 类」—— **覆盖不全，缺关键类别**

3 类没有覆盖：
- **「已修复 / 已变更」**（如 supply 已被补给、danger 已被处理、junction 路标已更新）—— 这是 mark 自然生命周期信号，不是负面信号，但用户唯一表达方式是 report「信息不符」，会被当作 SUSPICIOUS 触发器误处理。
- **「位置错误」**（GPS 漂移）—— 应该让作者修，不是 report。当前思想把它塞进「信息不符」，但语义完全不同。

「信息不符」一类承载了从 P0（资源消失）到 P3（GPS 偏移 10 米）的所有事情，严重度无法分级。

## 二、新攻击向量

### 2.1 「续命寄生攻击」(P0 新)

利用§四时钟 A「转化率系数加成」 + §六「寿命走完即死」组合：
- 攻击者建商业 mark
- 在 mark 即将寿命走完前，自己组织小团队（≤ 信誉权重过关数量）物理到场点 like
- 单位时间转化率瞬间拉满，续命系数把寿命续到极长
- 由于 HEALTHY 不冰冻、不冷却、不去重作者亲友，无机制识别这是「续命脉冲」
- mark 接近永生

产品层物理到场闸**没拦住**，因为攻击者真的到场了。三道闸里只有「IP / 设备封锁」可能识别，但小规模真人聚会无法拦。

**和 v6.1 「长期 wash 攻击」不同**：v6.1 攻击者改 sentiment 走向（拉高 like 比例），v6.2 是**单纯延长寿命**——不需要碾压 report 比例，只要在生命末期注入续命信号。

### 2.2 「假死复活攻击」(P1)

利用§六「DEAD 真不可逆」+ 「寿命走完即死」+ 强心剂概念脱节：
- 攻击者举报某 mark 进 SUSPICIOUS → CRITICAL → HEARTBEAT
- 在治疗机会即将耗尽时停手等寿命走完
- mark DEAD 后，作者**新建一个完全相同的 mark**（思想说「DEAD 真不可逆，用户须新建」）
- 新 mark 重新走冷启动，攻击者再来一遍

**「DEAD 不可逆」+「鼓励新建」组合让攻击成本周期性归零**。思想根本没讨论「重建 mark」是否被允许、是否有冷却。

### 2.3 「Report 类型降级攻击」(P1)

攻击者明明想干掉 mark，但选「不喜欢」（严重度低）而非「虚假广告」。
- 累积 100 个「不喜欢」report 表面看起来权重低
- 但思想说「占比驱动」「趋势驱动」—— sentiment 占比变红依然触发 SUSPICIOUS
- 攻击者用低严重度类型规避「严重度 × 信誉」加权，但仍然让 mark 进 ICU

思想没说低严重度 report 在「占比 / 趋势识别」环节是否同样降权，留下规避空间。

## 三、内在矛盾

### 3.1 「寿命定义」未定义（P0，最严重）
§三支柱 3 说续命系数延长寿命；§六说寿命走完即死。**两个寿命到底是不是同一个值？** 思想文档全程不说。这是核心矛盾。

### 3.2 「治疗机会」与「占比」语义冲突（P1）
§四：治疗机会 = new vote；§三：判定基于占比，不基于绝对数。
但「治疗机会数」是绝对数（高流量 mark 快速完成 vs 偏远慢慢完成）。这违反支柱 1。要么治疗机会按占比定义（如「新陌生人 vote 占近期 view 比例 ≥ X」），要么坦承部分判定靠绝对数，**思想里不能两边都说**。

### 3.3 「强心剂」与「连续函数」矛盾（P1）
§四「强心剂判定 = 近期赞占比足够高 + 独立用户数门槛」是**两个硬阈值**。§三明确「连续函数，无跨档跳跃」。强心剂触发 / 不触发是离散事件，不可能是连续函数。

## 六、修补建议（思想方向）

1. **明确「寿命」定义**：base 寿命 vs 累积续命寿命必须二选一并写清。建议「寿命 = base × 续命累积值，但有硬上限（例如 5 × base）」，兼顾续命与防永生。
2. **HEALTHY 状态引入「冬眠」选项**：type=danger 类 mark 在 0 view 时不冰冻但流失系数 < 1（缓慢衰减而非满速），区别于 scenic。这不破坏「HEALTHY 不冰冻」的精神，但承认 type 差异。
3. **续命脉冲检测**：寿命末期（最后 10%）的续命信号需要更高独立用户门槛，防止小团队续命寄生。
4. **重建冷却**：DEAD 后同一作者在同一 GPS 半径内 N 天不能重建同类型 mark。
5. **Report 类型补全**：增加「已变更/已修复」与「位置错误」两类，前者是 mark 自然终结信号（直接走向 DEAD 或归档），后者走作者修正流程而非 report 流程。
6. **Sentiment 占比环节也加严重度权重**：低严重度 report 在「趋势检测」中权重也应降低，否则形成规避漏洞。
7. **明确「治疗机会」是占比还是绝对数**：建议改为「治疗机会进度 = 新陌生人 vote / 期望 vote 数（基于近期流量推算）」，回归占比驱动。
