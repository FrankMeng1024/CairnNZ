# 口碑趋势识别研究报告

**调研时间**：2026-05-31
**调研范围**：2020-2026 年人类如何判断口碑、舆论、群体评价变化
**应用场景**：NZ 步道 mark 系统（一人一 mark 互斥赞/举报，无图无文，必须物理到场）

---

## 一、核心发现（5 条最重要的洞察）

1. **"质量 + 时效 + 数量 + 一致性" 四要素共识**：TripAdvisor Popularity Ranking 的官方公式明确把"评价的质量、时效、数量、以及一致性（consistency over time）"四个维度并列。这是工业界对"口碑可信度"的最简模型。任何只看其中一两项的评分都会被钻空子（700 条差评仍 4.9 的美团事件就是反例：缺"一致性"维度）。

2. **时间衰减不是线性**：小红书/今日头条类内容平台的热度算法都使用"前期保护期 + 后期加速衰减"的曲线——发布前 24h 几乎不衰减（让内容有传播窗口），过了有效传播期后衰减系数显著放大。这背后是牛顿冷却定律：`T(t) = H + (T₀ − H) · e^(−α·t)`，"温差越大、冷却越快"。

3. **Wilson Score 是工业基准**：Reddit、Steam、豆瓣的好评排序公认使用 Wilson 区间下界。它的关键性质是**当样本量小时主动惩罚分数**——5 个全赞的店比 50 个全赞的店得分低，这正是"早期口碑不能轻信"的数学化表达。Cairn 这种小样本场景几乎必须用它。

4. **"口碑崩塌"是平台主动需要防御的现象**：美团/大众点评在 2024-2025 年密集升级算法对抗"赠菜换好评""高频店内邀评"。核心做法是**评价权重而非算术平均**——评论者画像、评论质量、评论时效、是否真实消费都参与加权，单条评价不是"一票一分"。

5. **过期识别本质是"行为信号 + 时间窗口"组合**：地图类产品（高德/百度/Google Maps）识别商家关闭主要靠：长期无新评价/新签到 + 用户主动报错聚集 + 实地核查。没有任何一个平台只靠"时间够久了"就判定过期——必须有外部信号。

## 二、时间窗口设计——主流做法和数据

### 2.1 Hacker News（基准案例）

```
Score = (P − 1) / (T + 2)^G
P = 票数（减 1 抵消发帖人自投）
T = 距发布时间（小时）
G = Gravity，默认 1.8
```

含义：每过一小时，分母不是线性增长而是 1.8 次方加速。一篇 100 票的 8 小时帖（≈10/(10^1.8)≈0.16）会被一篇 30 票的 2 小时帖（≈30/4^1.8≈2.3）轻易超过。**重力参数 G 是调速旋钮**：G 越大，新内容上位越快、老内容沉底越快。

### 2.2 Reddit Hot Ranking

`hot = log(max(|score|,1)) + sign(score)·seconds/45000`
含义：每 12.5 小时，新帖能凭空获得 1 分的"年龄优势"——相当于让票数低 10 倍的帖子也能压过老帖。

### 2.3 牛顿冷却（小红书/今日头条采用）

`T(t) = H + (T₀ − H) · e^(−α·t)`
中文实践（多个 CSDN/简书帖证实）：
- α 通常按 24 小时半衰期取值（α = ln2/24 ≈ 0.029）
- 但前 6h 用更小的 α（保护期），让内容有传播余地
- 24h 之后 α 翻倍，加速沉底

### 2.4 衰减半衰期工业经验值

| 内容类型 | 半衰期 | 来源 |
|---|---|---|
| 突发新闻 | 4-8 小时 | 头条系算法 |
| 社交内容（小红书笔记） | 1-3 天 | 公开技术博客 |
| 商家评价（大众点评） | 6-12 个月 | 业内访谈推断 |
| 地点/POI 信息 | 12-24 个月 | 地图类产品惯例 |

**Cairn 适用区间**：步道 mark 介于"商家评价"与"POI 信息"之间——既有实时性（涨水危险一周后变化），又有半永久性（雪山观景点几年不变）。建议**按 mark 类型分桶设置半衰期**，不要一刀切。

## 三、趋势识别方法——平台用什么信号？

### 3.1 一致性（Consistency over Time）

TripAdvisor 官方明确把"评价是否一致"列为排名第四要素。**怎么算一致性？**业内常见两种方式：

- **滑动窗口方差**：把最近 N 条评价分成 K 个窗口（如 4 个窗口各 25%），算每个窗口的均值。窗口间方差越大 → 越不一致 → 信号衰减或降权。
- **新旧对比**：最近 30% 评价的均值 vs 最早 30% 评价的均值。差距 > 阈值 → 触发"趋势变化"信号。

### 3.2 加权平均而非算术平均

美团 2025 年公开声明："商家评分是通过多个因素计算每条评价的权重而得，并不是算数平均分"。权重因子包括：
- 评论者历史可信度（专业度）
- 评价文字质量
- 是否真实消费/到店
- 评价时效
- 是否符合反作弊规则

**对 Cairn 的启示**：每个赞/report 不是 1 分，应该按"用户历史信誉 + 到场置信度 + 时效"加权。

### 3.3 Wilson Score 区分"真好"与"少而幸运"

```
S = (p̂ + z²/2n − z·√(p̂(1−p̂)/n + z²/4n²)) / (1 + z²/n)
```

关键性质（多个技术博客一致总结）：
- **小样本主动减分**：n=5 全赞 ≈ 0.566；n=50 全赞 ≈ 0.929
- **永远不到 1**：避免"完美 5 星"假象
- **可比性**：不同样本量的 mark 可以直接排序

**Cairn 强烈推荐**：Wilson Score 替代赞数比例。z 取 1.96（95% 置信）或 1.28（80%，对小样本更宽容）。

### 3.4 异常检测（Review Bombing 防御）

亚马逊/Steam 的做法（行业披露）：
- **速率检测**：单位时间内的评价增长 > 历史均值 N 倍 → 标记可疑
- **聚类检测**：短时间内大量来自同一区域/同一行为模式的账户 → 屏蔽参与排名计算
- **AI 内容判别**：模板化文本、雷同评分行为 → 降权

**对 Cairn 的启示**：Cairn 已经有"必须物理到场"的硬约束（GPS 验证），等于天然防 brigade。但仍需防"组队上山刷赞"——可加：同一 mark 在 1 小时内来自同一上山起点的多账号 → 触发限速。

## 四、翻身机制——业界怎么给"二次机会"？

业界明确支持"reputation recovery"的设计极少（隐私和算法保密原因），但从公开技术资料可推断三种主流做法：

### 4.1 时间衰减天然支持翻身

由于老差评的权重在指数衰减，只要新好评持续涌入，**3-6 个月内评分就能自然回升**。这是最常见的"翻身机制"——平台不用做特殊处理。
- 大众点评的实际半衰期推测在 6-12 个月（差评 1 年后影响力 < 50%）

### 4.2 显式"近 N 条" vs "全部"双轨展示

TripAdvisor、Booking、Airbnb 都同时展示：
- 总体评分（全历史加权）
- "最近 12 个月"评分

这给用户主观判断"翻身"的机会——总体 3.5 但近 12 个月 4.6，用户会自己判断"这家最近改进了"。

### 4.3 趋势可视化（评分时间序列图）

App Store 评分页、Glassdoor 都有"评分按时间分布"的小图。这是把"翻身"判断权交还给用户——平台不下结论，但提供数据。

**对 Cairn 的启示**：与其设计复杂的"翻身算法"，不如让用户**直接看到 mark 的近期赞/report 比例变化**。展示比判断更可信。

## 五、过期识别——怎么知道"信息不再有效"？

这是最难的问题。业界没有银弹，只有信号组合：

### 5.1 行为消失信号（最强）

地图类产品识别"商家关闭"主要靠：
- 长时间（如 90 天）无新签到/无新评价/无新照片
- 同时点击量未消失（说明用户在尝试访问但没人核实存活）
- → 触发"该信息可能已过期"提示

### 5.2 主动报错聚集

百度地图/高德的"商家关闭""位置错误"举报，**当 7 天内来自不同用户的同类型举报达到阈值**（如 3 条），就降低该 POI 的展示权重并进入人工审核。

### 5.3 时间硬截止（兜底）

某些类型信息有强制 TTL：
- 餐厅菜单：90 天后置灰提示
- 商家营业时间：180 天未更新则标"信息可能不准"
- 临时活动/促销：自带过期日期

### 5.4 外部权威同步

Google Maps 与商家工商注册数据、运营商电话数据交叉校验。Cairn 没有这种数据源，但可以利用 **DOC（NZ Department of Conservation）的步道关闭公告**作为权威外部信号。

## 六、对 Cairn 的具体建议

基于前述研究，结合 Cairn 的产品约束（一人一 mark 互斥赞/举报、必须到场、无图无文、report 类型固定 6 种），算法设计建议如下：

### 6.1 评分公式——三层加权 Wilson Score

```
trust_score = wilson_lower_bound(
    pos = Σ(赞_i × user_credibility_i × recency_weight_i),
    neg = Σ(举报_j × user_credibility_j × recency_weight_j × report_type_severity_j),
    z = 1.28  # 80% 置信，对小样本宽容
)
```

**recency_weight 用分段衰减**：
- 0-30 天：weight = 1.0（保护期）
- 30-180 天：weight = exp(−ln2 × (days−30) / 180)（半衰期 180 天）
- 180+ 天：weight = max(0.1, exp(...))（保留 10% 底权重，老评价不归零）

**report_type_severity 区别对待**：
| Report 类型 | severity |
|---|---|
| 信息不实 | 1.5（最严重，影响真实性） |
| 已过期 | 1.2（影响时效但可修复） |
| 位置不对 | 1.5（同信息不实） |
| 不该来这 | 1.0（主观，但仍降权） |
| 冒犯 | 2.0（道德问题，最高权重） |
| 对我没用 | 0.5（个人偏好，弱权重） |

### 6.2 趋势识别——双窗口对比

每个 mark 维护两个窗口的 Wilson Score：
- **近 90 天窗口** `S_recent`
- **总体加权窗口** `S_overall`

**判定规则**：
- `S_recent < S_overall − 0.2` 且近 90 天样本数 ≥ 5 → **"信号衰退"** 标记，UI 显示淡化
- `S_recent > S_overall + 0.2` 且近 90 天样本数 ≥ 5 → **"翻身"** 标记，UI 可恢复显眼度
- 近 90 天样本数 < 5 → 仅展示 `S_overall`，避免小样本误判

### 6.3 过期识别——三信号组合

任一信号触发都进入"待核实"状态：

| 信号 | 阈值 | 处置 |
|---|---|---|
| 90 天内 0 条新赞 + 累计赞 ≥ 5 | 用户曾认可但近期无人验证 | UI 标记"近期无人确认" |
| 7 天内 ≥ 3 条"已过期"或"信息不实"报告 | 行为聚集 | UI 标记"可能已过期"，触发降权 |
| 距离创建 > 365 天 且 90 天内活跃度 < 10% 历史均值 | 双重老化 | UI 标记"信息较旧"，进入待核实队列 |

### 6.4 翻身机制——不要做特殊算法

**直接采用业界经验**：
- 时间衰减天然支持翻身（半衰期 180 天足够）
- UI 同时展示"总体可信度"和"近 90 天可信度"
- 让用户自己判断"这个 mark 最近又被认可了"
- **不要**设计任何"清零/重置"机制——会被滥用

### 6.5 防刷保障——利用物理到场约束

Cairn 的 GPS 到场是天然反作弊壁垒，但仍需补充：
- 同一 mark 在 1 小时内来自同一 trail entry GPS 区域的多账号赞 → 触发"集群行为"标记，降权 50%
- 单账号 24 小时内对同一区域多个 mark 全赞或全 report → 限速

### 6.6 核心思考模式总结

回到产品本质问题——**"这个 mark 现在还值得相信吗？"**——人类（和算法应该模仿的）思考是：

1. **看分层数据**：总体怎样？近期怎样？两者一致吗？
2. **看样本量**：5 个赞和 50 个赞含义完全不同，少样本必须保守
3. **看趋势方向**：上升/平稳/下降——下降比绝对分数更重要
4. **看一致性**：评价来源是否多样、时间是否分散
5. **不要做最终裁决**：把分层数据展示给用户，让用户自己判断——这是最稳健的设计

> 算法的目标不是"代替用户判断"，而是"让用户更快、更准地自己判断"。
