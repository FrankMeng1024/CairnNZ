## P0 漏洞(思想层关键缺失)

### P0-1:DEAD 远程复活的"历史信誉门槛"完全未定义

§六决策 1 + §三支柱 2 + Case O 都说"历史信誉好 → 可远程复活;差/无 → 真死",但**思想文档没说"历史信誉好"在逻辑上由什么构成**。

**矛盾点**:
- 文档强调"占比驱动,不是数字驱动"
- 但"历史信誉"必然是某种**累积量**(历史 like 总数?historical like/report 比?生前活跃天数?)
- 累积量本质上违反"滑动窗口而非累积"原则(决策 4)

**逻辑漏洞场景**:
- Case Z1:mark 历史 50 like 5 report 后 DEAD → 复活;mark 历史 5 like 0 report 后 DEAD → 不能复活?但后者比例(100% 正向)更好。"门槛"是数量还是比例?思想未答。
- Case Z2:mark 长期 HEALTHY 后被钓鱼攻击 SUSPICIOUS → CRITICAL → DEAD,死前 30 天连续负向。"历史信誉"看哪段?生前最后期还是全生命周期?思想未答。

**修补方向**:思想层必须定义"历史信誉的判定逻辑由什么构成"——例如"生前累积阶段的赞占比 + 独立用户多样性 + 生前曾达到过的最高状态等级"。具体数字在算法层,但**逻辑组成必须在思想层写清**。

### P0-2:DEAD 复活与"DEAD 真不可逆"是逻辑矛盾

§三状态机说 `DEAD → 可远程复活`,§九说"不防假死复活攻击——历史信誉门槛已设,复活是产品设计"。但**复活后的状态是什么没说**:

- 复活后回到 HEALTHY?寿命怎么算?从 0 开始?保留剩余寿命?
- 复活的 mark 是"新 mark 但保留信誉"还是"老 mark 续命"?
- **关键漏洞**:如果复活后寿命从满血开始 + 保留历史信誉权重 → **变成无限循环**:好 mark 死 → 复活 → 死 → 复活...这违反了"寿命走完即死的兜底机制"。

**修补方向**:思想层必须定义"复活后寿命起点 + 是否消耗某种'复活配额'"。否则"寿命走完即死"作为兜底机制就被掏空了。建议:复活有次数上限,或每次复活基础寿命递减,或复活后寿命起点低于初始 base。

### P0-3:"严重度全环节生效"对急转判定引入新矛盾

§五说严重度在"条数占比、趋势、急转、治疗机会"全环节生效。但**急转的定义是"近期 sentiment 占比 vs 远期 sentiment 占比的差异"**。

**逻辑漏洞**:
- 远期数据中 report 严重度未必被加权(早期 report 类型可能是旧版本生成的,或者远期采样窗口不同)
- 如果远期/近期都用"加权后等效信号"作差,**严重度高的少量 report 会让"急转"被永久触发**——只要近期出现 1 个虚假广告 report,加权后等效信号巨大,vs 远期的 0,差异无穷大。
- Case Z3:某 mark 一直 HEALTHY,运行 6 个月,从未被举报。第 181 天某新号 report"虚假广告"(严重度最高)→ 急转判定:近期严重度信号 = X,远期 = 0,差异 = X/0 = ∞ → 立刻 SUSPICIOUS。**单个高严重度 report 即可推 mark 进 ICU**,但思想说"低严重度 report 数量再多也难单独触发",反过来说**高严重度 1 条就能触发**——这真的是想要的行为吗?

**修补方向**:思想层必须明确"急转判定中,严重度加权信号的差值是绝对值还是占比";如果是占比,需引入"独立用户数门槛"作为防御(就像强心剂);否则单点钓鱼用 1 个虚假广告 report 即可击穿任何 mark。

## P1 漏洞(思想层重要不清)

### P1-1:HEALTHY → SUSPICIOUS 的"急转"边界未定义

§三状态机说"趋势急转向下 → SUSPICIOUS",但"急转"在思想层只说了"近期 vs 远期 sentiment 占比差异"。**"差异多少算急转"是数字问题(算法层),但"差异方向、对比窗口长度的逻辑关系"是思想问题**。

漏洞:
- 如果 mark 刚出生 1 天,"远期"窗口都没填满,怎么算急转?思想未答。
- HEALTHY 状态下 0 view 突然来 1 个 like → 近期 100% 正向 vs 远期 0 → 这也是"急转",但是急转向上,不该进 SUSPICIOUS。**思想没说"急转方向"如何区分向上向下**。

**修补方向**:思想层定义"急转必须满足:(1)方向向下 (2)远期窗口已具备最小样本量 (3)信号源多样性达标"。

### P1-2:SUSPICIOUS 中寿命走完的处理与"治疗机会"语义冲突

§三说"SUSPICIOUS 寿命走完 → DEAD(即使在治疗中也死)"。但 §四时钟 A 在 SUSPICIOUS+ 状态"冰冻(接近冻结)"。

**矛盾**:
- 如果时钟 A 在 SUSPICIOUS 已冰冻,寿命怎么走完?
- "接近冻结"vs"完全冻结"是数字问题,但**"冰冻状态下寿命是否会走完"是逻辑问题**。
- 如果会走完(只是慢),那么"冰冻给翻身机会"vs"寿命走完即死"是连续函数,SUSPICIOUS 状态下入院时寿命已经接近耗尽的 mark **可能进 ICU 几天就死**——治疗机会还没积累就 DEAD。这合理吗?

**修补方向**:思想层明确"SUSPICIOUS 入院时,如果剩余寿命 < 最小治疗机会窗口,如何处理"。建议:进 SUSPICIOUS 时给一个"最小救命期"保底窗口,即使原寿命已耗尽。

### P1-3:严重度组合的"占比加权"逻辑不清

§五"严重度全环节生效"。但 case 推算缺失**严重度组合场景**:
- Case Z4:mark 收到 100 个"不喜欢"(严重度最低)+ 1 个"虚假广告"(严重度最高)
- 严重度加权后等效信号是多少?
- 占比驱动的"report 占比"用原始条数还是加权信号?

**思想冲突**:
- 占比驱动支柱:基于"比例",所以应该用条数比例
- 严重度加权:应该用加权信号比例

**修补方向**:思想层必须明确"在占比计算中,分子分母用原始条数还是加权信号"。两者结果差异巨大。

### P1-4:"信号源多样性"门槛在 DEAD 复活中是否生效

§三支柱 2 提到"强心剂判定:近期赞占比 + 独立用户数门槛"。但 P0-1 提到的 "DEAD 远程复活的历史信誉" **是否包含独立用户数多样性**未说。

漏洞:作者朋友圈 5 个真人到场点 50 个 like(每人最多 1 票,所以是 5 票)→ DEAD 后历史信誉看似不错(50 like??不,只 5 like,因为 1 人 1 票) → 等等,1 人 1 票永久,那 50 like 必然是 50 独立用户,这条漏洞不成立。

**重新分析**:产品层"1 人 1 mark 1 票"已隐式保证独立用户数 = like 数。但**信誉权重不同**——50 个低权重新号 like vs 5 个高权重老号 like,加权后差异巨大。复活门槛是看条数还是加权值?思想未答。

## 新攻击向量(逻辑漏洞,非数字)

### 攻击 1:严重度跷跷板攻击

利用 P0-3:攻击者养 1 个老号(信誉过关),对目标 mark 偶尔(每隔半年)放 1 个"虚假广告" report → 急转判定:近期 1 个最高严重度信号 vs 远期 0 → 触发 SUSPICIOUS → 进 ICU。即使强心剂回退,攻击者每半年再来一次 → mark 永远在 ICU 边缘震荡。

### 攻击 2:复活循环

利用 P0-2:作者建好 mark → 朋友圈刷 like 进入 HEALTHY → 自然走完寿命 DEAD → 远程复活(历史信誉好)→ 重复。如果复活后寿命从满血开始,商业 mark 可永生。**这正是 §九否认的"假死复活攻击",但思想没给出门槛逻辑就否认了**。

### 攻击 3:急转方向歧义攻击

利用 P1-1:对刚出生 1 天的 mark(远期窗口未满)集中 like → 系统无法判定"急转向上"还是"急转向下" → 取决于算法层默认行为。如果算法层默认"任何急转都进 SUSPICIOUS",新 mark 第 1 天就进 ICU。

## 新内在矛盾

### 矛盾 1:"零数字"vs"历史信誉门槛"

思想层禁止数字,但"历史信誉好不好"必然涉及某种量化。**思想层应该定义"组成维度"和"维度间的逻辑关系"(例如"加权 like 数 ÷ 加权 report 数 > 某阈值 AND 独立用户数 ≥ 某阈值"),具体数字归算法层**。v6.3 完全省略了这一层抽象。

### 矛盾 2:"占比驱动"vs"DEAD 复活看历史"

占比驱动 + 滑动窗口(决策 3、4)否认累积,但"历史信誉"必然是某种生命周期累积。这两者必须在思想层调和——例如规定"复活判定用生前最后 N 天的滑动窗口占比 + 生前曾达到的最高状态等级"。

### 矛盾 3:"治疗机会驱动"vs"寿命走完即死"在 SUSPICIOUS 的优先级

参见 P1-2。两个机制谁优先在思想层未明确。

## §九思想边界审查

§九列出的不做项基本合理,但有 2 处该补未补:

1. **❌ 不防"急转方向歧义"**(P1-1) → 应补:思想层明确急转必须方向向下且样本充分
2. **❌ 不防"复活后再死再复活循环"**(P0-2) → 应补:复活有逻辑层面的次数/寿命衰减规则

§九"不防假死复活攻击——门槛已设"是**循环论证**——P0-1 指出门槛根本没在思想层定义。

## 总评

v6.3 的修补方向正确,但**新机制(渐近上限、DEAD 复活、严重度全环节)引入的判定逻辑都没在思想层走完**——多处停在"门槛已设"但没说门槛逻辑由什么构成。这违背了文档自己"思想完整,任何 case 都能推算"的承诺。

**核心建议**:思想层不写数字是对的,但**必须写"逻辑组成 + 维度间关系"**。当前 v6.3 在 DEAD 复活、急转判定两处把"逻辑组成"也省了,导致 subagent 拿这份思想推算 case 时,会得出不一致的结论。
