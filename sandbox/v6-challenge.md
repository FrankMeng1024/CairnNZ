# v6 思想 Challenge 报告

## 一句话评估

v6 在"季节性保护 / 偏远 mark / 流量自适应"三块漂亮地内置了解决方案；但在 **冷启动（无滑动窗口数据）**、**双时钟潜在冲突**、**治疗机会的"质量"未定义**、**信誉权重的冷启动 bootstrapping** 四个维度有结构性漏洞，攻击者读懂后可以系统性钻空。

完整度：**72/100**。建议补四个维度后实施。

---

## Case 测试（18 个）

### 经典场景

#### Case 1 — Tongariro Crossing 中段 danger（雪崩警告，1 月旺季）
- **场景**：Mangatepopo 谷地新警示，建立后 7 天内被 800 view、120 like、3 report
- **直觉判**：HEALTHY，强信号
- **v6 推算**：占比 like/(like+report) = 97.6% → HEALTHY；流量占比高 → 系数 1.0；治疗时钟未启动
- **覆盖度**：✅

#### Case 2 — Routeburn supply（水源点干涸）
- **场景**：建立 2 年累计 200 like，但近 3 周 0 like、5 report（"水源没了"）
- **直觉判**：SUSPICIOUS → CRITICAL
- **v6 推算**：远期 like 占比 95%，近期 sentiment 翻转为 0% → "急转"触发 SUSPICIOUS；后续治疗机会内继续 report → CRITICAL
- **覆盖度**：✅

#### Case 3 — Abel Tasman scenic 翻身
- **场景**：CRITICAL 状态（早期被 report 5 次"视野被挡"），3 个月后树倒了视野恢复，新 30 view 中 18 like 0 report
- **直觉判**：救回 SUSPICIOUS → HEALTHY
- **v6 推算**：近期 like 占比 100% 远高于历史，强心剂触发 → 回 SUSPICIOUS 观察
- **覆盖度**：✅

### 边界

#### Case 4 — Milford Track 冬季封山（5-9 月 0 view）
- **场景**：4 月底 SUSPICIOUS（治疗时钟启动了 2 个机会），5 月封山
- **直觉判**：状态冻结到 10 月
- **v6 推算**：双时钟暂停 → ✅
- **覆盖度**：✅

#### Case 5 — Fiordland Five Passes（月 1 view 偏远）
- **场景**：18 个月累计 22 view、3 like、1 report
- **直觉判**：维持 HEALTHY，零容忍误杀
- **v6 推算**：占比极低 → 系数大加成 → 寿命极长；趋势数据稀疏，难以触发急转
- **覆盖度**：🟡 — 思想说"占比加成"，但 1 个 report / 4 个 view = 25% report 占比，按占比驱动该不该触发 SUSPICIOUS？**思想没说占比阈值在小样本下怎么处理**

#### Case 6 — 新建 mark 第 1 周（Hooker Valley 新 supply）
- **场景**：建立后 3 天，10 view、2 like
- **直觉判**：HEALTHY 默认展示
- **v6 推算**：**滑动窗口里只有 3 天数据，"近期 vs 远期"对比不存在**；流量占比无基线；信誉权重对作者本人不适用
- **覆盖度**：🔴 — **冷启动空白**。文档第 254 行只是把这列为待 challenge 问题，没回答

### 攻击

#### Case 7 — Brigade 攻击（Queenstown 商业 mark）
- **场景**：竞争对手组织 50 个新号在 2 天内全部 report
- **直觉判**：识别并削弱
- **v6 推算**：50 新号信誉权重 0.3-0.5 + 跨 mark 集中举报权重 0.3 → 等效 report 数被削到约 7-8；产品层 IP 封锁再削一刀
- **覆盖度**：✅

#### Case 8 — 钓鱼攻击（养号 6 个月后集中举报）
- **场景**：攻击者 6 个月前注册 30 个号，期间均衡 like/report 累积"行为均衡"信誉，第 7 个月对目标 mark 集中 report
- **直觉判**：必须识别
- **v6 推算**：注册时间 > 30 天 → 权重 1.0；行为均衡历史 → 权重 1.0；**唯一能识别的是"跨 mark 集中举报短期"，但攻击者只对 1 个 mark 集中**——这条规则无法触发
- **覆盖度**：🔴 — **信誉权重的攻击向量**。养号 + 单点集中 = 完全合法行为画像

#### Case 9 — 商业 mark 自吹（Wanaka 偏远咖啡推广）
- **场景**：作者朋友圈 8 人路过 like，真用户极少
- **直觉判**：识别为低质
- **v6 推算**："只 like 不 report"权重 0.5 → 8 人等效 4 like；偏远 mark 占比低 → 系数加成寿命长 → **寿命加成反而保护了它**
- **覆盖度**：🟡 — 思想 Case I 自己承认"仍有边缘风险"

#### Case 10 — 假强心剂攻击
- **场景**：mark 进 CRITICAL 后，攻击者（或商家自己）用养号在 2 天内集中 like 5 次拉占比
- **直觉判**：不该把它救回来
- **v6 推算**：近期 like 占比飙升 → 触发强心剂 → 回 SUSPICIOUS；信誉权重对"养号 + 行为均衡"识别失败（同 Case 8）
- **覆盖度**：🔴 — **强心剂判定本身没有"质量"维度**，只看占比

### 反直觉

#### Case 11 — Roy's Peak 高 view 低互动网红打卡
- **场景**：日均 500 view，但 90% 用户开 AR 看一眼就走，互动 < 5%
- **直觉判**：HEALTHY
- **v6 推算**：流量占比高 → 系数 1.0；like > report → HEALTHY ✅
- **覆盖度**：✅

#### Case 12 — Mt Eden 持续争议（一半喜欢一半讨厌）
- **场景**：长期累计 like : report ≈ 50:50，没有明显趋势
- **直觉判**：用户群分层，不该死
- **v6 推算**："急转"=近期 vs 远期占比差异，长期 50:50 → 没有急转 → 维持当前状态；但**思想没说初始稳定 50:50 mark 的初始状态是什么**——HEALTHY 还是 SUSPICIOUS？
- **覆盖度**：🟡

#### Case 13 — Ruapehu 火山警戒级别变化
- **场景**：danger mark 建立时 GeoNet 1 级，半年后升到 3 级，老 like 仍在但实质风险已变
- **直觉判**：算法管不了，外部信号
- **v6 推算**：算法只看互动，不看外部 → 思想第 9 节明确不做语义分层
- **覆盖度**：✅（明确不在范围内）

### 时钟交互

#### Case 14 — 双时钟冲突场景
- **场景**：偏远 mark 进 SUSPICIOUS（时钟 B 启动），整个冬天 0 view，但时钟 A 也在跑（缓慢）
- **直觉判**：希望整体冻结
- **v6 推算**：文档 §四 说"没人 view 期间衰减更慢"和"时钟 B 暂停"——**两套时钟在 0 view 时都暂停？还是 A 慢跑 B 暂停？文档自相矛盾**
  - §四第 102 行："没 view 期间衰减更慢（基本不老化）"
  - §六决策 1："**所有**时钟暂停"
- **覆盖度**：🔴 — **内在矛盾：时钟 A 在零 view 期是"慢跑"还是"暂停"？**

#### Case 15 — 治疗中爆火
- **场景**：CRITICAL 状态偏远 mark 突然 Twitter 爆火，1 天 1000 view
- **直觉判**：快速验证下结论
- **v6 推算**：治疗机会快速积累 → 1 天判命运；如果 1000 view 中 800 like → 强心剂回 SUSPICIOUS；但**1 天内连续 1000 个治疗机会，是不是该有"机会冷却"？**否则攻击者控制流量节奏 = 控制治疗时长
- **覆盖度**：🟡 — **治疗机会数没定义"机会的质量/独立性"**

### 滑动窗口边界

#### Case 16 — Aoraki 新 mark 第 1 月（同 Case 6 延伸）
- 见 Case 6，🔴

#### Case 17 — 老 mark 远古数据被忘
- **场景**：5 年前 200 like 的健康 mark，最近 2 年 0 view，突然 30 个 report
- **直觉判**：要慎重，可能是新风险也可能是攻击
- **v6 推算**：滑动窗口只看近期 → 远期 200 like 历史"被忘" → 30 report 看起来像 100% 负向 → 急转 SUSPICIOUS；信誉权重削一些；如果 30 个全是新号 → 削大半
- **覆盖度**：🟡 — **完全丢弃远期历史合理吗？** 5 年好评积累在算法里没有任何重量

#### Case 18 — 时钟暂停 + DEAD 永驻问题
- **场景**：mark 在 HEARTBEAT 状态被封山冻结 5 年，5 年后山区改名 / 路线废弃，永远 0 view
- **直觉判**：实际上死了，但算法上永远 HEARTBEAT
- **v6 推算**：时钟暂停 → 永远 5% 展示——**资源浪费 + 永远不会让位给新 mark**
- **覆盖度**：🔴 — **薛定谔状态没有兜底机制**

## 内在矛盾

1. **时钟 A 在零 view 期的状态自相矛盾**（Case 14）。§四 vs §六决策 1 不一致。必须二选一。
2. **DEAD 不可逆 vs 时钟暂停**：Case 18 揭示了——一个永远 0 view 的 HEARTBEAT mark 永远不会变 DEAD。**HEARTBEAT 是比 DEAD 更糟糕的状态**（占用 5% 展示却毫无价值）。
3. **占比驱动 vs 小样本统计**：Case 5 / Case 6——占比在 n=4 时和 n=400 时不能用同一阈值，但思想没区分。
4. **滑动窗口 vs 历史信任**：Case 17——5 年好评的 mark 与新建 mark 在算法眼里等价，违反"信任需要时间累积"的基本直觉。

## 漏掉的维度

### 1. 冷启动机制（最关键）
- 新 mark 第 1 周怎么活？没有滑动窗口数据怎么算占比？
- 新用户信誉权重默认值？默认 1.0 = 攻击者拿新号占便宜；默认 0.5 = 真实新用户被打压
- 思想里只有"权重低（0.3-0.5）"，但没区分新用户的"已观察行为"和"零行为"

### 2. 治疗机会的质量定义
- 1 个 IP 同一用户 1 小时点 100 次 view 算 100 个治疗机会还是 1 个？
- 攻击者控制流量节奏 = 控制治疗时长（Case 15）
- 思想里"new view = 一次治疗"过于简单

### 3. 滑动窗口长度策略
- 思想 §决策 4 说"算法自决"——但短窗口对偏远 mark 太敏感、长窗口对爆火反应慢，**这是真实的 trade-off，不能甩锅给"自适应"**
- "多窗口加权"听起来对，但加权系数从哪来？

### 4. HEARTBEAT 兜底
- 永远没人 view 的 HEARTBEAT mark 该多久后强制 DEAD？
- 或者：寿命走完即使 0 view 也强制 DEAD（让 mark 真正退场）
- 这是双时钟设计的副作用，思想没处理

### 5. 历史权重衰减曲线
- 不能完全丢弃远期历史也不能等同新近数据，需要明确衰减函数
- 思想说"滑动窗口"但没说窗外的数据是 0 还是有低权重

### 6. 攻击者画像特征
- 信誉权重的 6 维度都基于"用户行为"，没有"行为时间分布"维度（Case 8 钓鱼攻击）
- 攻击者养号成本低、收益高，需要更隐式的信号（IP 重叠、设备指纹辅助进入算法层做软权重）

## 攻击者视角

### 钻"占比驱动"
- **节奏控制**：在攻击窗口前主动制造大量"无意义 view"稀释 report 占比，等过了窗口再集中 report
- **小样本陷阱**：对新建 mark（Case 6）第一时间用 3 个新号 like 把占比锁死成 100%——后续真用户即使 report 也撑不动占比

### 钻"治疗机会"
- **机会消耗攻击**：让目标 mark 进 SUSPICIOUS 后，用养号大量"路过 view"快速消耗治疗机会，不投票 → 治疗时钟跑完但没有强心剂 → 强制升级
- **机会瘫痪**：反向，让自己的商业 mark 进 SUSPICIOUS 后**主动减少曝光**（删自己社交分享、不出现在 trending）→ 治疗时钟暂停 → 永远不下沉

### 钻"信誉权重"
- **养号 + 单点集中**（Case 8 钓鱼）：6 个月均衡行为，第 7 个月对单 mark 集中 report，所有信誉维度都过关
- **共谋互赞**：100 个号互相 like 对方的"日常 mark"建立"行为均衡 + 历史可信"，攻击日全员 1.2 权重

### 钻"时钟暂停"
- **永生 HEARTBEAT**（Case 18）：让目标 mark 进 HEARTBEAT 后切断流量来源（社交平台撤下分享、SEO 不优化）→ 永远 5% 展示资源浪费
- **永生争议**（Case 12 延伸）：人为维持 50:50 占比，让 mark 永远不进救命期也不彻底健康

## 必修补丁清单（按优先级）

### P0（必须，否则不能上）
1. **解决双时钟冲突**：明确"零 view 期时钟 A 完全暂停"或"慢速跑"二选一，写死
2. **冷启动机制**：新 mark 前 N 个 view（如 50）按"信任默认 + 强制收集多样信号"运行，不走占比驱动
3. **HEARTBEAT 兜底**：HEARTBEAT 状态超过寿命双倍且持续低 view → 强制 DEAD（避免薛定谔永驻）
4. **治疗机会去重**：同一信誉权重用户在窗口期内多次 view 只算 1 次治疗机会

### P1（强烈建议）
5. **新用户信誉冷启动**：注册 < 30 天 + 行为 < 5 次 → 权重 0.5（不是 0.3，避免冤杀）；行为 ≥ 5 次后按维度加权
6. **历史权重衰减**：远期数据不丢，按指数衰减进入信任分（而非 0 / 1）
7. **滑动窗口策略**：明确"双窗口"——短窗口（趋势识别 7 天）+ 长窗口（基线建立 90 天），不是"自适应"甩锅

### P2（值得做）
8. **行为时间分布维度**：信誉权重补一条"行为时间均匀性"，识别养号集中爆发模式
9. **强心剂质量校验**：强心剂触发需要"独立用户数 ≥ N"和"信誉权重和 ≥ M"双门槛，不仅看占比
10. **争议 mark 长期处理**：50:50 长期争议 mark 单独标记，UI 层展示但算法不进救命期
