## 二、新发现 P0 漏洞

### P0-NEW-1：冰冻矛盾——时钟 A 在"无投票"时仍在跑，但治疗时钟 B 要求"必须有投票才推进"

§四明确：
- 时钟 A 流失速度 ≈ `base × 趋势系数 × 流量系数`，0 view 时 = 0.005（**仍在流失**）
- 时钟 B：无投票 = **完全暂停**

**矛盾场景**：mark 进入 SUSPICIOUS，0 view 持续 2 年。
- 时钟 B 暂停 → 永远无法判"治疗失败"
- 时钟 A 在缓慢跑 → base 寿命走完
- §四"真死的双重条件 = 寿命走完 + 治疗失败"——治疗永远没失败，怎么判死?

**两种解读，都坏**：
1. 寿命走完 + B 暂停 → mark 永远卡 SUSPICIOUS（v6 的 HEARTBEAT 永驻问题换了位置复活）
2. 寿命走完即 DEAD（不需 B 失败）→ §四自我否定，且 Case A（雪崩警告冬季）会被冤杀

**思想方向**：要么 B 在长期无投票后强制超时（违反"投票即治疗"），要么 A 在生病期同步冻结（违反"不绝对暂停"）。**v6.1 没有给出选择**。

### P0-NEW-2：趋势系数引用循环

§四"时钟 A 流失速度 = base × 趋势系数 × 流量系数"，§四又写"持续无新投票 → 趋势系数 0.05"。

**问题**：趋势是 sentiment 比例的变化。**0 投票时 sentiment 比例没有定义**——比例的分母是 0。怎么算趋势?

如果回答"0 投票 = 趋势降级到 0.05"，那么"趋势"和"流量"实际上是同一个信号的两个名字（都由"近期投票数"驱动），系数相乘 = 同一信号的平方衰减，§三"占比驱动"被破坏（占比变成数字驱动的代理）。

### P0-NEW-3：滑动窗口的攻击面（v6.1 没解决）

§十问题 3 自己提出来但没回答。**具体攻击**：

攻击者知道窗口是 30 天。在第 1-29 天集中 like 把"近期 sentiment 占比"做成 95% 正向，第 30 天集中 report——窗口边缘前一天看是 HEALTHY，后一天突然出现"急转向下"——但**急转的对照基准（远期 sentiment）是攻击者自己刚 wash 出来的假数据**。

强心剂质量校验也救不回来：因为强心剂判定也用同一个滑动窗口的同一段假数据。

**思想方向**：远期基准必须用**不可回写**的累积统计（与§三"不用累积数据"冲突）。这是支柱 1 与支柱 3 的内在矛盾。

## 三、新发现 P1 漏洞

### P1-1：分档系数 1.0 / 0.5 / 0.2 / 0.05 是阈值伪装

§三"硬阈值是错的"，但§四自己用了 4 档硬阈值。**边界攻击**：

攻击者把 mark 维持在"趋势下降"边缘（0.5）vs"急转向下"（0.2）的临界点反复横跳。每次跨档系数 ×2.5 跳变 → 寿命估计也跳变 → UI 展示策略可能跟着跳。

**连续函数（如 sigmoid）确实更好**——分档是为了"思想清晰"，但思想清晰不等于决策稳健。这是 v6.1 没回答§十问题 7。

### P1-2：流量系数 0.1 vs 0.3 vs 1.0 同样是 3 档阈值

同 P1-1。"低 view 0.3"和"0 view 0.1"差 3 倍，但用户体感"低"和"零"是连续渐变的。

### P1-3：HEARTBEAT 永驻"不占感知资源"是诡辩

§九 ❌"不防 HEARTBEAT 永驻——0 view 不占用户资源"。

**反例**：偏远 supply mark（"溪边可饮水"）实际已废弃（溪干了），但作者每年带 1 个朋友物理到场点 1 个 like。
- 1 like / 年 → 不是 0 view → 流量系数不会降到 0.1
- HEARTBEAT 5% 展示 = 真用户**有概率看到**
- 真用户走 3 小时到溪边发现没水 → 高代价误导

§九的"0 view 不占资源"前提**和§四"低 view 0.3 系数"打架**——什么叫 0 view? 月 1 view 算 0 吗? **思想里没定义"零"的边界**，导致漏洞。

### P1-4：作者不能自赞 ≠ 第一个 like 来自陌生人

§三 J："作者不能给自己点赞，所以第一个 like 必然来自陌生人"。

**反例**：作者建 mark 后让朋友（同行队友）物理到场点 like。**朋友是陌生人吗?** 算法层无法分辨。冷启动声称的"用同一套算法"在此暴露——头 5 个 like 全来自作者社交圈，转化率系数会把这个 mark 推到很高寿命，**强心剂质量校验失效**（独立用户数门槛在 5 个朋友面前不工作）。

**思想方向**：冷启动期需要"信誉权重 + 时间分散"双重要求，不能只靠"作者自赞禁令"。

## 六、修补方向（不给方案，只给思想）

1. **P0-NEW-1**：双时钟必须共享一个"长期沉默超时"机制，否则"投票即治疗"和"冰冻原则"在生病期不可共存。
2. **P0-NEW-2**：趋势和流量必须由**不同信号源**驱动，否则系数相乘等于平方衰减，违反占比思想。
3. **P0-NEW-3**：远期基准必须脱离滑动窗口（部分累积），承认"占比驱动"在抗 wash 攻击时需要混合策略。
4. **P1-1/P1-2**：所有分档系数改连续函数，思想里写"连续映射"而不是"4 档"。
5. **P1-3**：定义清楚"零 view"的边界，HEARTBEAT 在年级别零 view 后必须真死。
6. **P1-4**：冷启动需要"独立用户数 + 时间分散"，不能只靠作者禁赞。
7. **§九**：增加"官方账号豁免"和"语义分层下沉到 v7"。
